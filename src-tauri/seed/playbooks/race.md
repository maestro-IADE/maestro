# 경쟁 실행

같은 과제를 워커 여러 명에게 동시에 맡기고, 결과를 같은 기준으로 비교해 가장 좋은 것을 고르는 절차예요. 기본 지휘(`default.md`)의 공통 규칙을 함께 따라요.

## 구성

| 역할 | 페르소나 | 인원 | 맡는 일 |
|---|---|---|---|
| 경쟁 | `~/.maestro/personas/implementer.md` | 2–3 | 같은 명세를 각자 다른 방법·에이전트로 구현 |
| 비교 | `~/.maestro/personas/reviewer.md` | 1 (선택) | 이름을 가린 브랜치들을 같은 기준으로 비교 |

## 언제

- 접근 방법이 여러 가지라 무엇이 나을지 모를 때
- 에이전트(Claude Code, Antigravity)나 모델끼리 비교하고 싶을 때
- 한 번에 잘 나와야 하는 중요한 변경

## 절차

1. **명세 하나.** 과제를 기능 명세 형식으로 한 번 정리한다(무엇을, 범위, 완료 증거). 모든 워커에게 같은 문장을 준다
2. **차이 정하기.** 후보마다 무엇이 다른지 한 줄로 정한다(방법, 에이전트, 모델). 차이가 없으면 경쟁할 이유가 없다
3. **비교 기준 정하기.** 띄우기 전에 고를 기준을 적어 둔다(예: 테스트 결과, 바꾼 범위, 읽기 쉬움, 성능). 결과를 본 뒤 기준을 바꾸지 않는다
4. **띄우기.** 워커를 2–3명 한꺼번에 만든다
   ```
   maestro worktree create --name race-a --prompt "<명세>"
   maestro worktree create --name race-b --agent antigravity --prompt "<명세>"
   ```
   방법을 달리하려면 명세 끝에 "이 방법으로: …"를 각자 다르게 붙인다
5. **기다리기.** 턴을 끝내고 완료 메모를 기다린다. 모두 끝날 때까지 비교하지 않는다
6. **비교.** 브랜치마다 같은 명령을 Lead가 직접 돌려 결과를 모은다(워커 보고의 숫자를 옮겨 적지 않는다). 비교 워커를 쓰면 어느 워커·에이전트 것인지 가리고 A/B/C로만 준다
   | 후보 | 차이 | 바꾼 파일 수 | 테스트(직접 돌림) | 장점 | 문제 |
   |---|---|---|---|---|---|
7. **고르기.** 3번 기준으로 하나를 고르고 이유를 사용자에게 보고한다. 진 쪽의 좋은 부분이 있으면 고른 워커에게 `maestro send`로 옮겨 달라고 한다
8. **합치기.** 사용자가 고른 안에 동의하면 `evidence-gate.md`를 거쳐 합친다

## 주의

- 명세가 다르면 비교가 안 된다. 같은 문장을 그대로 보낸다
- 진 워커의 워크트리는 사용자가 지운다(에이전트는 지우지 않는다)
