# 나눠서 구현

큰 기능을 겹치지 않는 조각으로 나눠 워커들이 동시에 만들고, Lead가 순서대로 합치는 절차예요. 기본 지휘(`default.md`)의 공통 규칙을 함께 따라요.

## 구성

| 역할 | 페르소나 | 인원 | 맡는 일 |
|---|---|---|---|
| 나누기 | `~/.maestro/personas/planner.md` | 1 (선택, 큰 일일 때) | 조각과 인터페이스 정리 |
| 구현 | `~/.maestro/personas/implementer.md` | 조각 수만큼 | 조각 하나씩 |
| 테스트 | `~/.maestro/personas/tester.md` | 1 (선택) | 합친 뒤 전체 확인 |

## 언제

- 한 명이 하기엔 크고, 서로 다른 파일이나 모듈로 나눌 수 있을 때
- 예: 백엔드 API / 프론트 화면 / 테스트·문서

## 절차

1. **나누기.** 기획자처럼 작업을 쪼갠다. 조각마다
   - 고쳐도 되는 파일(조각끼리 겹치지 않게)
   - 다른 조각과 맞춰야 할 인터페이스(함수 이름, 타입, API 모양)
   - 완료 증거(돌릴 명령과 기대 결과)
   인터페이스를 먼저 정해서 모든 조각 명세에 똑같이 적는다
2. **공유 파일 주인 정하기.** 여러 조각이 건드릴 파일(`CHANGELOG`, `package.json`, `Cargo.toml`, lockfile, 라우터·등록 목록 등)은 조각 하나에만 맡기거나, 모두 끝난 뒤 Lead가 한 워커에게 한 번에 맡긴다
3. **계약 먼저(필요할 때).** 조각들이 같은 타입이나 스키마를 코드로 공유해야 하면, 그것만 만드는 작은 워커를 먼저 돌려 기준 브랜치에 합친 뒤 나머지를 띄운다
4. **맡기기.** 서로 기다릴 필요 없는 조각은 한꺼번에 띄운다. 역할이 있으면 페르소나를 잇는다
   ```
   maestro worktree create --name api --prompt "<조각 명세>"
   maestro ref add --to api --path ~/.maestro/personas/implementer.md
   ```
5. **지켜보기.** 턴을 끝내고 완료 메모를 기다린다. `## 보고`를 읽고, 막힌 워커에게는 `maestro send`로 답한다
6. **범위 확인.** 합치기 전에 바뀐 파일이 그 조각의 허용 파일 안인지 본다(`git diff --stat <기준>...<브랜치>`). 벗어났으면 이유를 묻고, 필요 없으면 되돌리게 한다
7. **합치기.** 조각마다 `evidence-gate.md`를 거쳐, 의존 순서대로(먼저 쓰이는 쪽부터) 하나씩 합친다. 합칠 때마다 프로젝트 폴더에서 빌드와 테스트를 돌리고, 실패하면 다음 조각을 합치지 않고 멈춘다
8. **마무리.** 모두 합친 상태에서 전체를 한 번 더 돌린다(조각별 결과는 합친 뒤의 증거가 아니다). 사용자에게 조각별 결과와 남은 일을 보고한다

## 주의

- 두 워커가 같은 파일을 고치게 나누지 않는다. 피할 수 없으면 순서를 정해 하나가 끝난 뒤 다음 워커를 시작한다
- 인터페이스를 바꿔야 하면 모든 관련 워커에게 같이 알린다
- 워커는 자기 조각의 테스트만 돌린다. 전체 테스트는 Lead가 합칠 때 돌린다
