# 메뉴, 확인 창, 토스트

## 요약

되돌리기 어렵거나 무언가를 잃는 동작은 앱 안의 확인 창 하나로 물어요. 브라우저 기본 확인 상자(`confirm()`)는 쓰지 않아요. 확인 창은 메인 창과 분리 창 모두에서 같은 모양이고, 떠 있는 동안 터미널이나 캔버스가 키를 가져가지 않아요. 오류는 위 가운데의 토스트로 알려요. 메뉴(⋯ 버튼과 우클릭)도 부품 하나(`Menu`)로 그려요. 사이드바(프로젝트, 에이전트 행), 탭 줄(탭 우클릭, 묶음 ⋯), 에이전트 헤더 ⋯가 모두 이것을 써요.

## 동작

**메뉴**
- ⋯ 버튼을 누르면 버튼 바로 아래에, 우클릭하면 포인터 자리에 떠요. 아래에 자리가 없으면 위로 열리고, 창 밖으로 나갈 자리면 창 안쪽 8px까지 밀려 들어와요.
- 모양: 최소 폭 200px, 안쪽 4px, 모서리 10px. 항목은 높이 28px(안쪽 좌우 10px, 13px 글, 왼쪽 14px 아이콘은 흐린 글자색, 사이 8px, 모서리 6px). 단축키가 있으면 오른쪽에 11px 흐린 글자로 보여요. 위험한 항목(지우기·빼기)은 글자와 아이콘이 빨강이에요. 묶음 사이는 가는 선.
- 닫히는 때: 항목을 고름, Esc, Tab, 메뉴 밖을 누름, 메뉴 밖의 휠, 메뉴가 달린 곳을 움직이는 스크롤(페이지나 그곳을 품은 상자), 창이 포커스를 잃음, 창 크기가 바뀜. 에이전트가 답을 쓰는 동안 채팅이 따라 내려가거나 터미널이 출력으로 밀려도, 그 안에서 연 메뉴가 아니면 닫히지 않아요. 열려 있는 ⋯ 버튼을 다시 누르면 닫혀요.
- 키보드: 열리면 메뉴가 포커스를 받아요. ↑/↓로 항목 사이를 돌고(흐린 항목은 건너뜀), Home/End로 처음·끝, Enter나 Space로 골라요. 열린 동안 키는 메뉴만 받아요(터미널, 캔버스, 창 단축키가 받지 않음). 닫히면 열기 전 포커스 자리로 돌아가요.
- 메뉴는 한 번에 하나예요. 다른 메뉴를 열면 앞의 것이 닫혀요.
- 캔버스 카드에서 열어도 메뉴 위에서 끌거나 휠을 굴려 캔버스가 움직이지 않아요.
- 메뉴를 연 줄은 메뉴가 열린 동안 hover 버튼이 계속 보여요.

**확인 창**
- 폭 440px, 안쪽 20px, 모서리 16px. 제목(14px, 600) 아래에 설명(13px, 두 번째 글자색, 줄바꿈 유지)이 있고, 경로·파일 이름이 필요하면 작은 고정폭 상자에 보여요(8개까지, 넘으면 "… 외 N개").
- 오른쪽 아래 [취소] [동작 이름]. 동작 이름 버튼은 무엇을 하는지 말해요("폐기", "목록에서 제거", "저장하지 않고 닫기" 등).
- 무언가를 지우거나 잃는 동작(위험)이면 확인 버튼이 빨간 면이고, 처음 포커스가 [취소]에 있어요. Enter는 포커스된 버튼을 눌러요. 그래서 위험한 확인은 Tab으로 확인 버튼에 옮겨 가야 Enter로 확인돼요.
- 위험하지 않은 확인은 처음 포커스가 확인 버튼이고, Enter로 바로 확인돼요.
- Esc, 바깥(어두운 바탕) 누르기, [취소]는 모두 취소예요.
- 떠 있는 동안 포커스는 창 안 두 버튼 사이에서만 돌아요(Tab, Shift+Tab). 다른 곳(터미널 등)이 포커스를 가져가려 하면 창이 되찾아요. 닫히면 열리기 전 포커스 자리(터미널, 편집기)로 돌아가요.
- 확인 창이 여러 개 요청되면 하나씩 차례로 떠요. 다른 대화상자(설정 등)보다 위에 떠요.

**확인 창을 쓰는 곳**
| 곳 | 제목 | 확인 버튼 | 위험 |

| 사이드바 프로젝트 추가, 고른 폴더가 Git 저장소가 아님 | Git 저장소가 아니에요 | Git 저장소로 만들고 추가 | 아니요 |

**토스트(오류 알림)**
- 위쪽 막대 바로 아래 가운데(막대에서 8px)에 떠요. 폭은 440px(창이 좁으면 양옆 16px를 남겨요).
- 한 개: 빨간 `CircleAlert` 아이콘 + 오류 글(12px, 6줄까지, 넘으면 잘려요) + 오른쪽 X(24×24). 글은 선택해서 복사할 수 있어요.
- 8초 뒤 저절로 닫혀요. 마우스를 올려 둔 동안은 멈추고, 내리면 남은 시간부터 다시 세요. X를 누르면 바로 닫혀요.
- 여러 개면 아래로 8px 간격으로 쌓여요(새 것이 아래). 3개까지 보이고, 넷째가 오면 가장 오래된 것이 닫혀요.
- 이미 떠 있는 것과 같은 글이 또 오면 새로 쌓지 않고 그 토스트 뒤에 "×2", "×3"처럼 붙이고 8초를 다시 세요.
- 대화상자(설정 등)보다 위, 확인 창보다 아래에 떠요. 메인 창과 분리 창이 각자 자기 토스트를 보여요.

**입력 대화상자(새 에이전트, 에이전트 설정)**
- 폭 480px, 안쪽 24px, 필드 사이 16px, 모서리는 다른 대화상자와 같아요. 제목 14px/600 + 왼쪽 16px 아이콘.
- 라벨은 12px/500 흐린 글자로 필드 6px 위에 있고, 고르지 않아도 되는 칸은 라벨 뒤에 11px "선택". 입력칸·선택 상자는 높이 32px, 13px, 안쪽 좌우 10px.
- 바닥 오른쪽 [취소] [주 버튼 + 키캡 "Ctrl ↵"(10px 고정폭)], 높이 32px. Ctrl+Enter가 주 버튼이고, 한 줄 입력칸의 그냥 Enter는 아무것도 하지 않아요. Esc와 바깥 클릭은 닫기(저장·만드는 중 제외).
- 오류는 바닥 위 상자(모서리 6px, 안쪽 8px 12px, 12px 빨간 글 + 같은 색 8% 면). 설정에서 고칠 수 있으면 오른쪽에 "설정에서 설치" 같은 글 버튼이 있고, 누르면 설정 창이 그 대화상자 **위에** 떠요(닫으면 쓰던 대화상자로 돌아와요).
- 창이 낮으면 대화상자 안이 스크롤돼요(창 높이 − 64px까지).
→ [에이전트 만들기](../worktrees/create-worktree.md), [에이전트 설정](../agents/agent-settings.md)

- 잃는 작업이 있는 폐기는 버튼 세 개(취소 / 버리기 / 보관)가 필요해서 따로 된 폐기 창이에요. 폭·안쪽 여백·버튼은 확인 창과 같아요. → [워크트리 폐기](../worktrees/discard-worktree.md)

- **에이전트 메뉴는 어디서나 같아요**: 사이드바 행(⋯, 우클릭), Lead 캔버스의 워커 카드(⋯, 우클릭), 프로젝트 지도 카드(우클릭)가 같은 항목을 보여요(`useAgentMenu`, src/agentMenu.tsx).

## 구현

- `src/ui/Menu.tsx`
  - `openMenu(at, items, { owner?, minWidth? })`. `at`은 `{ x, y }`(우클릭, `pointOf(e)`) 또는 요소(⋯ 버튼, 그 아래에 열림). 항목은 `{ label, icon?, shortcut?, danger?, disabled?, onSelect }` 또는 구분선 `"sep"`. `closeMenu()`.
  - 모듈 안에 열린 메뉴 하나(`current`)를 두고 `useSyncExternalStore`로 `<MenuHost />`가 읽어요. `MenuHost`는 `document.body` 포털로 그리고, 창마다 `WindowLayers`(Workspace.tsx)에 한 번 있어요(메인 창, 분리 창).
  - 위치: `useLayoutEffect`에서 크기를 재고(`place`) 그리기 전에 자리를 정해요. 재기 전에는 `visibility: hidden`이라 화면 밖에 한 프레임도 보이지 않아요.
  - `owner`(기본: `at`이 요소면 그 요소)에 열린 동안 `data-menu-open`을 붙여요. 줄의 덮는 hover 버튼이 이 속성으로 계속 보여요.
  - 닫기: `window`의 캡처 `pointerdown`(메뉴 밖), `wheel`(메뉴 밖), `scroll`(`scrollClosesMenu(target, anchor, inMenu)`: 스크롤한 것이 문서이거나 메뉴의 기준 요소를 품을 때만. 기준 요소는 ⋯ 버튼이면 그 버튼, 우클릭이면 열 때 그 점의 요소(`elementFromPoint`)), `blur`, `resize`. 테스트: `scripts/chrome-check.ts`. ⋯ 버튼을 눌러 닫은 직후의 클릭은 같은 메뉴를 다시 열지 않아요(`shutBy`, 0.8초).
  - 키: 열린 동안 `window` 캡처 `keydown`을 먼저 받아 전파를 끊어요(확인 창과 같은 방식). IME 조합 중이면 건드리지 않아요.
  - 루트 클래스 `menu nodrag nopan nowheel`: React Flow가 이 클래스 아래의 끌기·이동·휠을 무시해요.
  - 스타일(styles.css): `.menu`(z-index 65: 대화상자 50·토스트 60 위, 확인 창 70 아래), `.menu-item[data-hot|data-danger]`, `.menu-icon`, `.menu-label`, `.menu-key`, `.menu-sep`. 높이는 `var(--h-head)`.
- `src/ui/Confirm.tsx`
  - `ask({ title, body?, list?, confirm, danger? }): Promise<boolean>`. 모듈 안의 대기열(`queue`)에 넣고, 확인하면 `true`, 취소하면 `false`로 풀려요.
  - `<ConfirmHost />`: `useSyncExternalStore`로 대기열을 읽어 맨 앞 요청 하나를 `document.body` 포털로 그려요. 창마다 한 번 마운트해요: 메인 창 `App`(App.tsx), 분리 창 `WorkspaceWindow`(Workspace.tsx). 마운트된 곳이 없으면 요청은 대기열에서 기다려요.
  - 키: 창이 떠 있는 동안 `window`의 캡처 단계 `keydown`을 먼저 받아 전파를 끊어요(xterm, React Flow, 창 단축키가 받지 않음). Esc = 취소. Enter는 포커스가 창의 버튼이면 브라우저 기본 동작(그 버튼 누르기), 아니면 위험하지 않을 때만 확인. Tab은 두 버튼 사이를 돌아요. IME 조합 중(`isComposing`)이면 건드리지 않아요.
  - 포커스: 처음에 위험이면 취소, 아니면 확인 버튼. `document`의 `focusin`(캡처)이 창 밖으로 간 포커스를 되돌려요. 닫힐 때 열리기 전의 `activeElement`로 돌려줘요.
  - `askDiscardEdits(rel)`: 저장하지 않은 파일을 닫을 때의 확인(탭 막대와 코드 보기가 같이 써요).
- 토스트
  - 스토어(store.ts): `toasts: Toast[]`, `pushToast(text)`, `dropToast(id)`. `setError(e)`는 모양이 그대로(`(e: unknown) => void`)이고, 값이 있으면 `String(e)`를 `pushToast`, 빈 값이면 토스트를 모두 닫아요(예전 `setError("")` 호출 호환). 예전 `error` 문자열 필드는 없앴어요.
  - `withToast(list, text, id, at)`(ui/toastList.ts, 순수 함수): 같은 글 합치기(`n` + 1, `at` 갱신)와 3개 제한. `scripts/chrome-check.ts`가 시험해요.
  - `<Toasts />`(ui/Toasts.tsx): 토스트마다 남은 시간을 기억하는 타이머. `onMouseEnter`/`onMouseLeave`로 멈추고 이어 가요. `at`이 바뀌면(같은 글이 또 옴) 8초부터 다시 세요. `Workspace.tsx`의 `WindowLayers`로 메인 창과 분리 창에 한 번씩 있어요.
  - 스타일: `.toasts`(고정 위치 `top: calc(var(--h-chrome) + 8px)`, z-index 60, 쌓임 사이 클릭은 통과), `.toast`, `.toast-text`(6줄 자르기), `.toast-count`, `.toast-x`. 색은 테마의 `--mae-toast-bg`, `--mae-toast-text`, 아이콘 `--mae-err`.
- 스타일(styles.css): `.confirm-backdrop`(z-index 70, 다른 `.modal-backdrop` 50보다 위), `.modal.confirm`(폭 440), `.confirm-body`, 목록은 폐기 창의 `.discard-list`를 그대로 써요. 위험 버튼 `button.danger-fill`(`--mae-err` 면, 흰 글자).
- 입력 대화상자: `.modal.form-dialog`(폭 480, 안쪽 24, 사이 16)와 `.field`, `.field-label`, `.field-opt`, `.field-hint[data-warn|data-err]`, `.field-row`(두세 칸 한 줄), `.advanced`(접힌 고급 줄), `.facts`(읽기 전용 두 칸 표), `.dialog-error`, `.dialog-foot`, `.dialog-status`, `kbd.keycap`. 다른 `.modal`(문서 고르기, 폐기 등)은 그대로예요. `WindowLayers`는 새 에이전트 창 → 에이전트 설정 창 → 설정 창 순으로 그려서 같은 z-index(50)에서 설정 창이 위에 와요.
- 호출부는 이벤트를 먼저 처리(`stopPropagation`)한 뒤 `await ask(...)`해요. 폐기는 확인 전에 `busy`를 푸는 순서(`setBusy(null)` → 묻기 → `finish`)를 그대로 둬요. 채팅↔터미널 전환(`useRuntimeSwitch`)은 묻는 동안 더 새로운 전환이 있었으면(`mine()`이 거짓) 확인해도 진행하지 않아요.

## 제약과 알려진 문제

- 확인 창은 한 번에 하나만 보여요. 앞의 것을 닫아야 다음 것이 떠요.
- 토스트는 잠깐 탭 줄 일부를 가려요. 8초 뒤 사라지고 X로 바로 닫혀요. 오류가 아닌 알림(성공 등)은 아직 토스트로 보내지 않아요.
- 6줄을 넘는 오류 글은 토스트에서 잘려 보여요.
- 창 밖 클릭으로 취소되는 것은 위험한 동작에서도 같아요(취소 쪽이라 안전해요).
- 메뉴 안에 하위 메뉴는 없어요.

## 결정 기록

- 2026-11-14: 사이드바 행 메뉴를 `useAgentMenu` 훅으로 꺼내 워커 카드와 지도 카드도 같은 메뉴를 쓰게 했어요. 캔버스 안내가 "우클릭과 ⋯로 메뉴"라고 했지만 캔버스 카드에는 메뉴가 없었어요.
- 2026-11-13 (리뷰 수정): 아무 스크롤에나 닫히던 것을 기준 요소를 움직이는 스크롤에만 닫히게 했어요. `window`의 캡처 `scroll`은 모든 요소의 스크롤을 받는데, 그중 많은 것이 코드가 한 스크롤이에요(채팅의 `useStickyScroll`, xterm의 출력, 사이드바·탭 막대의 `scrollIntoView`). 에이전트가 일하는 동안 헤더 ⋯ 메뉴가 50ms 안에 닫혀 고를 수 없었어요. 사용자의 스크롤은 `wheel`로 닫혀요.
- 2026-11-13 (UI 구조 재구성 단계 1): 브라우저 `confirm()` 10곳을 `ask()` 하나로 바꿨어요. 기본 확인 상자는 앱 모양과 다르고, 버튼 이름이 "확인/취소"뿐이라 무엇을 하는지 말하지 못하고, 떠 있는 동안 앱 전체를 멈춰요. 창마다 그려야 해서 메인 창과 분리 창에 각각 `ConfirmHost`를 둬요.
- 위험한 확인에서 Enter가 바로 확인하지 않게 했어요. 터미널에서 Enter를 치던 손이 그대로 폐기를 확인하는 일을 막아요.
- 2026-11-13 (UI 구조 재구성 단계 2): 오류 토스트를 아래 가운데에서 위 가운데로 옮기고 쌓이게 했어요. 아래 가운데는 캔버스 입력창, 오른쪽 아래는 미니맵 자리라 오래 떠 있으면 일을 막았어요. 예전 토스트는 한 개뿐이고 눌러야 닫혀서, 새 오류가 앞의 것을 덮어썼어요. 8초 자동 닫힘, 같은 글 합치기, 3개 제한은 Orca의 토스트 규칙을 참고했어요.
- 2026-11-13 (UI 구조 재구성 단계 6): 탭 우클릭 메뉴를 예전 `.ctx-menu`(창 `mousedown`으로만 닫히고 키보드가 안 되던 것)에서 `Menu`로 옮기고, "다른 탭 닫기"와 묶음 메뉴, 에이전트 헤더 ⋯를 더했어요. 에이전트 메뉴의 분할·새 창·복사는 사이드바 행 메뉴와 같은 함수(`agentActions.ts`)를 불러 두 곳이 어긋나지 않아요.
- 2026-11-13 (UI 구조 재구성 단계 3): 메뉴 부품 하나(`Menu`)를 만들었어요. 메뉴마다 따로 그리면 위치 보정, 닫히는 조건, 키보드, 캔버스 위에서의 끌기 막기가 곳마다 달라져요. 포털로 그려 사이드바·카드의 `overflow: hidden`에 잘리지 않아요. 프로젝트 제거 확인의 입구가 머리의 X에서 프로젝트 메뉴 끝으로 옮겨졌어요.
- 2026-11-13 (UI 구조 재구성 단계 8): 입력 대화상자 규칙(480/24/16, 라벨 위, 32px 칸, 바닥 오류 상자, Ctrl+Enter)을 새 `.form-dialog`에만 줬어요. `.modal` 기본값(400/20/12)을 바꾸면 문서 고르기·구조 편집 같은 다른 창이 한꺼번에 흔들려서, 두 창부터 옮기고 나머지는 그 화면을 고치는 단계에서 맞춰요.
