# 가운데 화면 탭

## 요약

가운데 화면(스테이지) 위에 32px 탭 줄이 있어요. 첫 탭은 항상 프로젝트(또는 문서·플레이북)이고, 그 뒤로 에이전트와 파일이 붙어요. 탭 하나는 앞 아이콘 하나, 이름, 닫기 버튼이에요. VS Code처럼 한 번 클릭하면 "미리보기 탭"으로 열리고, 다음 클릭이 그 자리를 다시 써서 탭이 마구 쌓이지 않아요. 편집하거나, 메시지를 보내거나, 더블클릭하면 탭이 고정돼요. 줄 오른쪽에는 전체 화면 ↔ 캔버스, 오른쪽으로 분할, 묶음 메뉴(⋯)가 늘 같은 자리에 있어요. Ctrl+1…9로 N번째 탭에 가고, 다녀온 곳은 위쪽 막대의 ← → 버튼이나 Alt+←/→로 뒤로/앞으로 오가요.

## 동작

**탭 모양**(안쪽 좌우 8: 앞 아이콘 16 → 6 → 이름 12px → 4 → 닫기 16, 폭 120~240, 탭 사이 1px 선)
| 탭 | 앞 아이콘 | 이름 |
|---|---|---|
| 에이전트 | 승인 대기·작업 중·새 응답이면 상태 글리프, 아니면 에이전트 로고 12(흐리게 .7). 둘을 같이 그리지 않아요. 에이전트가 없는 외부 워크트리는 빈 원 | 새 응답이면 굵게(500) |
| 파일 | `File` 14 | 변경 비교면 이름 뒤에 `GitCompare` 12(툴팁 "변경 비교") |
| 프로젝트 | `Folder` 14 | 굵게(500), 최대 160px |
| 문서·플레이북 | 보고 있는 보드에 따라 `FileText` "문서" / `BookOpen` "플레이북" | 굵게(500) |

**탭 종류**
- **문서·플레이북:** 사이드바 `문서`·`플레이북`을 누르면 다른 프로젝트를 여는 것처럼 열려요. 첫 탭이 "문서" 또는 "플레이북" 탭이 되고, 연 문서는 그 뒤 탭으로 붙어요. → [시스템](system-tab.md)
- **프로젝트 탭(첫 탭):** 폴더 아이콘과 프로젝트 이름이 굵게 보여요. 묶음에 프로젝트 탭 하나뿐이면 열린 탭 표시(위쪽 막대)를 그리지 않아요(구분할 탭이 없어서).
  - ×(또는 휠 클릭)로 닫으면 그 묶음이 탭들과 함께 사라져요(메인 창의 마지막 묶음이면 프로젝트 없이 남아요). 탭들은 기억해 뒀다가 그 프로젝트를 다시 열면 닫기 전 그대로 되살려요. 마지막에 닫은 프로젝트 하나는 앱을 다시 켜도 기억해요(localStorage `maestro.lastClosedProject`).
  - 저장하지 않은 파일이 있을 때만 확인 창으로 물어요("'<이름>' 탭을 닫을까요?", 그 파일 목록, [닫기]). 그 편집은 사라져요. → [메뉴와 확인 창](menus-and-dialogs.md)
  - 끌면 그 묶음 전체가 옮겨져요(분할·합치기·창 밖 새 창). → [워크스페이스](split-and-windows.md)
- **에이전트 탭:** 앞 아이콘 하나(위 표)와 이름. 툴팁은 이름과 브랜치예요.
- **파일 탭:** 파일 아이콘과 이름. 변경 비교면 비교 아이콘이 붙어요.
- 탭은 프로젝트마다 따로예요.

**오른쪽 묶음**(왼쪽 1px 선, 24×24 버튼 셋)
- **전체 화면 ↔ 캔버스**(에이전트 탭이 화면에 있을 때만): 지금 전체 화면이면 `Workflow` "캔버스로 보기", 캔버스면 `Maximize2` "전체 화면으로 보기". 두 보기에서 같은 자리예요. 그 탭만 바꾸고 설정은 건드리지 않아요. 새 탭이 처음 여는 화면은 설정이 정해요(마에스트로는 캔버스, 다른 에이전트는 전체 화면). → [2단계 캔버스](../canvas/two-level-canvas.md)
- **오른쪽으로 분할**(`Columns2`): 지금 탭을 옆 묶음에 하나 더 열어요.
- **묶음 메뉴**(`Ellipsis`): 오른쪽으로 분할 · 아래로 분할 · 이 묶음을 새 창으로(메인 창에서만, 탭이 있을 때) · ─ · 다른 탭 모두 닫기(지금 화면의 탭만 남겨요). 프로젝트 탭을 우클릭해도 이 메뉴가 떠요.

**탭 우클릭 메뉴**
- 오른쪽으로 분할 · 아래로 분할 · 새 창으로 열기 · 탭 고정(미리보기일 때) · 에이전트 설정…(에이전트가 붙은 탭) · ─ · 닫기 · 다른 탭 닫기.
- "다른 탭 닫기"는 그 탭만 남기고 화면에 그 탭을 보여 줘요. 저장하지 않은 파일이 섞여 있으면 확인 창으로 물어요("다른 탭을 닫을까요?", 그 파일 목록, [닫기]). 묶음은 닫히지 않아요.
- 메뉴는 앱 공용 메뉴예요(↑↓ Enter, Esc, 바깥 클릭에 닫힘). → [메뉴와 확인 창](menus-and-dialogs.md)

**키**
- Ctrl+1…9: 포커스된 묶음의 N번째 탭으로 가요. 프로젝트 탭이 1번이에요(탭 줄에 보이는 순서). 그보다 탭이 적으면 아무 일도 없어요. 미리보기 탭은 미리보기로 남아요.
- 입력칸, 편집기(Monaco), 터미널에 포커스가 있으면 키를 그쪽에 둬요. → [단축키](shortcuts.md)

**미리보기 탭(VS Code 방식)**
| 하는 일 | 결과 |
|---|---|
| 파일 트리·변경 목록에서 파일 한 번 클릭 | 미리보기 탭으로 열려요 |
| 사이드바에서 워크트리 한 번 클릭 | 미리보기 탭으로 열려요 (더블클릭하면 고정 탭) |
| 다음 것을 또 한 번 클릭 | 새 탭 없이 미리보기 탭 자리가 바뀌어요(미리보기 탭은 늘 하나) |
| 파일 더블클릭, 파일 편집 | 그 파일 탭이 고정돼요 |
| 캔버스에서 카드 더블클릭, 지도의 "마에스트로 열기" 버튼 | 고정 탭으로 열려요 |
| 워크트리 채팅에서 메시지 보내기 | 그 워크트리 탭이 고정돼요 |
| 탭 더블클릭 | 언제든 고정돼요 |
| 열린 화면(캔버스, 에이전트, 편집기) 안 아무 데나 더블클릭 | 지금 탭이 고정돼요 |
- 미리보기 탭은 이름이 한 단계 흐린 색(`--mae-text-2`)이고, 마우스를 올리면 "미리보기 탭 · 더블클릭하면 고정"이 보여요. 기울임꼴은 쓰지 않아요(Pretendard에 이탤릭이 없어 한글이 기울어지지 않았어요).
- 이미 열린 것을 다시 열면 새로 만들지 않고 그 탭으로 가요. 고정된 탭은 미리보기로 돌아가지 않아요.

**뒤로 / 앞으로**
- 위쪽 막대의 ←(뒤로) →(앞으로) 버튼이에요(브랜드와 왼쪽 패널 토글 다음). 분할해도 자리가 그대로예요. 갈 곳이 없으면 흐리게 꺼져요. → [창 프레임](window-frame.md)
- 키: Alt+← / Alt+→. 입력칸, 편집기(Monaco), 터미널에 포커스가 있거나 대화상자가 떠 있으면 키를 그쪽에 둬요. → [단축키](shortcuts.md)
- 탭을 옮기거나, 프로젝트를 바꾸거나, 파일을 열 때마다 기록돼요(최대 50개). 뒤로 간 상태에서 새 곳으로 가면 앞쪽 기록은 지워져요(브라우저와 같아요).
- 그 사이 닫혔거나 다른 미리보기로 바뀐 탭으로 돌아가면, 그 탭이 미리보기로 다시 열려요.
- 프로젝트가 목록에서 빠졌거나 워크트리가 폐기된 기록은 건너뛰어요.

**닫기**
- 닫기(16×16, `X` 12)는 열린 탭에서는 늘, 나머지 탭은 마우스를 올리거나 키보드 포커스가 탭 안에 있거나(Tab으로 닫기 버튼에 옴) 그 탭의 메뉴가 열려 있으면 보여요. 휠(가운데 버튼) 클릭으로도 닫혀요.
- 저장 안 한 파일은 닫기 자리에 6px 점이 보이고(마우스를 올리면 `X`), 닫을 때 확인 창으로 물어요.
- 열린 탭을 닫으면 바로 왼쪽 탭(없으면 오른쪽, 그것도 없으면 프로젝트)으로 가요.
- 워크트리를 폐기하면 그 워크트리 탭과 그 안의 파일 탭이 함께 닫혀요.

**순서 바꾸기**
- 탭을 같은 탭 줄 위에서 좌우로 끌면 순서가 바뀌어요. 놓일 자리에 강조색 세로선이 보여요.
- 다른 묶음의 탭 줄에 놓으면 그 자리에 끼워 넣어요(`dropTab`의 `index`, `placeAt`).
- 프로젝트 탭은 항상 맨 앞이에요.

**탭이 많을 때**
- 탭은 이름을 줄여 가며 최소 120px까지 좁아져요(프로젝트 탭은 그대로).
- 그래도 넘치면 탭 줄 양끝에 ‹ ›(20×24) 화살표가 생겨 2/3 화면씩 넘겨요. 탭 줄 폭이 260px 이하면 화살표를 숨겨요. 마우스 휠로도 옆으로 넘기고, 열린 탭은 항상 보이는 자리로 스크롤돼요.

**모양**
- 탭 줄은 32px(`--h-bar`)이고 탭은 각진 모양이에요. 탭 사이는 세로 선으로 나눠요.
- 열린 탭은 위쪽에 2px 선이 있고, 바탕이 아래 화면과 같은 색이라 이어져 보여요. 선은 포커스된 묶음에서만 강조색이고 나머지 묶음은 테두리 색이에요.
- 다른 탭에 갔다 와도 저장 안 한 편집은 그대로예요(파일 편집기를 숨긴 채 살려 둬요).

**분할과 새 창**
- 탭 줄은 탭 묶음마다 하나예요. 분할, 탭 옮기기, 새 창은 → [분할 화면과 새 창](split-and-windows.md)

## 구현

**상태**(store.ts)
- `tabs: Record<프로젝트 루트, StageTab[]>`
  - `StageTab`은 `{ kind: "wt", path }` 또는 `{ kind: "file", base, rel, diff }`이고, 둘 다 `preview?`가 있어요.
- `withTab(tabs, root, tab, pin)`
  - 이미 있는 탭이면 자리를 그대로 두고, 이번에도 미리보기로 열 때만 미리보기로 남겨요.
  - 새 탭이면 `pin`일 때 끝에 붙이고, 아니면 기존 미리보기 탭 자리를 대신해요(없으면 끝에 붙여요).
- 탭을 여는 함수
  - `select(path, pin?)`: 워크트리로 가요. 편집기도 함께 내려요(`editor: null`). 프로젝트를 바꾸는 `setActive`, `addRepo`도 편집기를 내려요.
  - `openEditor(e, pin?)`: 파일을 열어요.
- `pinTab(tab)`: 미리보기를 고정해요. 부르는 곳은 세 군데예요.
  - `CodeView`: 편집이 생겼을 때
  - `Composer`(AgentNode.tsx): 보낸 뒤
  - `StageTabs`: 탭을 더블클릭할 때
  - App.tsx `.stage-body`: 화면 안을 더블클릭할 때
- 지금 화면의 탭은 저장하지 않고 `activeTab`으로 계산해요(열린 파일 → 고른 워크트리 → 프로젝트).
- `closeTab`: 화면의 탭을 닫으면 이웃 탭으로 한 번에 옮겨 가요. 그래서 중간 상태가 기록에 남지 않아요.
- `closeOthers(groupId, keep)`: `keep`만 남기고(null이면 다 닫고 프로젝트) 그것을 보여 줘요. 닫는 파일의 초안(`wsDraftSet`)과 `dirtyFiles`도 지워요. 묶음은 탭이 없어도 남아요. 남긴 것이 파일이면 그 아래 에이전트 탭이 사라졌으니 `path`를 비워 프로젝트를 깔아요.
- `barTabs(group, s)`: 탭 줄이 보여 주는 순서(프로젝트 탭 = null, 워크트리가 사라진 에이전트 탭은 뺌). Ctrl+1…9가 이 순서로 세요. `openTab(t)`: 탭을 누른 것과 같아요(파일은 `openEditor`, 나머지는 `select`, 미리보기 여부 유지).
- `useTabLayout(group)`: 화면의 에이전트 탭이 전체 화면인지 캔버스인지. 탭의 `layout`이 있으면 그것, 없으면 역할의 첫 화면(`roleLayout`). `GroupView`와 탭 줄 토글이 같이 써요.
- `dirtyFiles`, `setFileDirty`: 저장 안 한 파일 목록이에요.

**뒤로/앞으로 기록**
- `nav: { list: Nav[], i }`. `Nav`는 `{ root, path, editor }`예요.
- `useStore.subscribe`가 위치가 바뀔 때마다 `i` 뒤를 잘라내고 새 위치를 붙여요. 같은 위치면 붙이지 않아서, 뒤로 가기 자체는 기록을 늘리지 않아요.
- `navTarget(s, dir)`는 갈 수 있는(`navValid`) 가장 가까운 기록을 찾아요. `goNav(dir)`는 그 위치를 그대로 되살리고, 탭이 없으면 미리보기로 다시 만들어요.

**화면**
- `StageTabs`: 왼쪽은 탭 목록(`.stage-tab-list`, 가로 스크롤), 오른쪽(`.tab-actions`)은 `LayoutToggle`(`setTabLayout`만 불러요), 분할, 묶음 메뉴예요. 메뉴는 `openMenu`(ui/Menu.tsx)로 열어요(예전 `.ctx-menu`는 없앴어요).
- 에이전트 탭 앞 아이콘은 `AgentTabIcon`: `glyphState`가 승인 대기·작업 중·새 응답·에이전트 없음이면 `StatusGlyph`, 쉬는 중·꺼짐이면 로고(`.tab-logo`, opacity .7).
- `.stage-tabs`는 CSS 컨테이너(`container-type: inline-size`)라 `@container (max-width: 260px)`에서 넘침 화살표를 숨겨요. `data-lone`(보이는 탭이 없음)이면 프로젝트 탭의 위쪽 선을 지워요.
- 뒤로/앞으로 버튼은 `NavButtons`(Workspace.tsx)로 창 위쪽 막대에 한 번 있어요. 키는 `useShortcuts`(ui/useShortcuts.ts)가 같은 `goNav`를 불러요. Ctrl+1…9도 `useShortcuts`가 `tabNumber(e)`(shortcuts.ts)로 번호를 읽어 처리해요.
- zustand v5는 셀렉터가 매번 새 객체나 배열을 돌려주면 끝없이 다시 그려요. 그래서 `StageTabs`는 스토어 값을 그대로 고르고(`repos`에서 찾은 프로젝트, `worktrees`, `dirtyFiles`, `systemView`), 탭 목록은 셀렉터가 아니라 `group` prop(`group.tabs`)으로 받아요.
- App.tsx는 모든 프로젝트의 파일 탭마다 `CodeView`를 띄우고, 화면의 것만 `active`예요.

## 제약과 알려진 문제

- 탭 목록과 뒤로/앞으로 기록은 앱을 다시 켜면 사라져요. 마지막 워크트리 탭 하나만 고정 탭으로 다시 생겨요.
- Ctrl+1…9는 채팅 입력창에 포커스가 있으면 동작하지 않아요(입력칸은 키를 그대로 받아요).
- 마우스 뒤로/앞으로 버튼은 아직 연결하지 않았어요.
- 화면에서 확인하지 않았어요.

## 결정 기록

- 2026-11-13 (리뷰 수정): 닫기 버튼을 `:focus-within`과 `[data-menu-open]`에서도 보이게 했어요. 닫기는 진짜 `<button>`이라 Tab이 모든 탭의 닫기에 오는데, `opacity: 0`이 전역 `:focus-visible` 테두리까지 숨겨 포커스가 어디 있는지 보이지 않았어요. 사이드바 행과 같은 덮개 규칙이에요.
- 탭 없이 화면이 그냥 바뀌니 어디서 왔는지 놓친다는 의견에서 탭을 넣었어요. 프로젝트·워크트리·파일을 한 줄에 쌓는 쪽을 골랐어요.
- 누를 때마다 새 탭이 생기는 게 번거롭다는 의견에, VS Code의 미리보기 탭 정책을 그대로 따랐어요.
- 탭은 처음의 둥근 34px 모양에서 얇고(28px) 각진 모양으로 바꿨어요.
- 2026-11-13 (UI 구조 재구성 단계 6): 탭 앞 아이콘을 하나로 줄였어요(상태가 있으면 상태, 없으면 로고. Orca의 탭 앞 아이콘 방식). 글리프와 로고를 나란히 그리면 탭 폭의 절반이 아이콘이었어요. 미리보기 탭의 기울임꼴은 Pretendard에 이탤릭이 없어 한글에서 티가 안 나서 흐린 색으로 바꿨어요. 레이아웃 토글은 전체 화면에서는 헤더 끝, 캔버스에서는 떠 있는 상자로 자리가 달랐고 설정까지 바꿔서 "마에스트로 캔버스"가 채팅을 열었어요. 탭 줄 오른쪽 한 자리로 모으고 그 탭만 바꾸게 했어요. 새 창 버튼은 묶음 메뉴로 넣어 버튼 줄을 셋으로 줄였어요(탭 끌기·우클릭은 그대로 한 번). 탭이 많을 때 "다른 탭 닫기"가 없다는 문제도 같이 풀었어요. Ctrl+1…9는 탭 줄에 보이는 순서대로 세서 프로젝트 탭이 1번이에요(보이는 것과 키가 어긋나지 않게).
- 2026-11-13 (UI 구조 재구성 단계 2): 뒤로/앞으로를 마지막 탭 묶음의 탭 줄 끝에서 위쪽 막대로 옮겼어요. 분할하면 버튼 자리가 움직였고, 기록은 원래 창 하나에 하나라 묶음마다 둘 이유가 없었어요.
- 2026-11-13 (UI 구조 재구성 단계 8): 에이전트 탭 우클릭 메뉴에 "에이전트 설정…"을 더했어요(에이전트가 붙은 탭만, "탭 고정" 다음). 탭 더블클릭은 "탭 고정"이라 이름 바꾸기에 쓰지 않아요.
