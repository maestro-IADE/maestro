# 문서(Maestro 공용 문서)와 페르소나, 참조

## 요약

문서는 Maestro가 직접 관리하는, 모든 프로젝트가 같이 쓰는 마크다운이에요. 페르소나(`~/.maestro/personas`)와 분류별 폴더(`~/.maestro/library/<분류>/`)로 나뉘고, 처음부터 기본 제공 파일이 들어 있어요. Lead가 워커를 부리는 절차는 따로 **런북**(`~/.maestro/playbooks`)이에요. 프로젝트처럼 여는 **시스템**(카드 대시보드)과 에이전트 캔버스의 **문서** 버튼 패널에서 보여 줘요. 문서를 캔버스로 끌어 에이전트에 이으면 "참조"가 돼요. 참조는 파일 경로를 가리킬 뿐 파일을 복사하지 않아요. 프로젝트 자기 문서는 따로 등록하지 않고 오른쪽 파일 트리에서 끌어와요.

## 동작

- **기본 제공 파일**: 앱에 내장돼 있다가(`src-tauri/seed/`) 처음 실행할 때 빠진 것만 채워져요. 지운 기본 파일은 다시 생기지 않고, 고친 파일은 덮어쓰지 않아요.
  - 새 판 받기(2026-11-20): 앱이 기본 파일을 쓸 때마다 그 글의 지문을 폴더의 `.shipped`에 적어 둬요. 앱이 시작할 때 파일이 적어 둔 지문 그대로면(손대지 않음) 지금 앱에 든 새 판으로 바꿔요. 고친 파일은 그대로 두고, 그런 파일은 `기본값으로`로 새 판을 받아요. 지문을 적기 전에 깔린 파일은 고쳤는지 알 수 없어서 고친 파일처럼 다뤄요.
  - 이름 바꾸기(2026-11-19): 예전 앱이 깔아 둔 기본 파일에 런북의 옛 이름이 남아 있으면 앱이 시작할 때 그 낱말만 "런북"으로 바꿔요. 폴더마다 한 번이고(`.renamed` 표시), 고친 내용은 그대로 두며, 사용자가 만든 파일은 건드리지 않아요(`library.rs` `rename_runbooks`, 시험 `built_in_files_take_the_runbook_name_once`).
  - 페르소나: 기획자, 구현 담당, 리뷰어, 테스터, 아키텍트, 디자이너, 문서 담당, 검증 담당(`verifier.md`), 반증 담당(`skeptic.md`), 디버거(`debugger.md`)
  - 지침: 에이전트 공통 규칙(CLAUDE.md 시작점), 코딩 규칙, 커밋과 PR 규칙
  - PRD: PRD 템플릿, 기능 명세 템플릿, 결정 기록(ADR) 템플릿
  - 디자인: 디자인 원칙, UI 점검표, 모션 가이드
  - RAG: RAG 문서 작성 규칙, 용어집 템플릿, 문제 해결 기록 템플릿
  - 런북: 기본 지휘, 아키텍처 먼저, 경쟁 실행, 나눠서 구현, 구현 → 리뷰 반복, 계획 먼저, 근본 원인 디버깅(파일 `bug-hunt.md`), 증거로 완료 판정(`evidence-gate.md`), 승인 후 실행(`approve-then-act.md`), 여러 관점 리뷰(`multi-lens-review.md`). 모두 맨 위에 `구성` 표(역할, 페르소나 파일, 인원, 맡는 일)가 있어요. Lead는 워커를 만들 때 이 표대로 페르소나를 이어요
- **런북 규칙의 뼈대** (2026-11-16 개정):
  - 기본 지휘(`default.md`)의 `공통 규칙`은 모든 런북에 적용돼요. 다른 런북은 첫 문단에서 "기본 지휘의 공통 규칙을 함께 따라요"라고 가리켜요. 담는 것: 역할 경계(Lead는 구현하지 않음, 사용자의 맡기는 방식 지시가 우선), 맡기지 않는 경우(질문, 몇 번의 조회, 확인용 빌드·테스트), 명세에 넣을 것(산출물, 고쳐도 되는 파일, 공유 파일 주인, 정한 것과 버린 것, 완료 증거), 기다리기와 수렴(폴링 금지, 독립 작업 먼저 띄우기, 쓸 만하면 새 워커 안 만듦, 이중 지시 금지), 완료 판정(완료 메모 ≠ 일 끝), 승인 후 실행, 실패와 반복(조용한 대체 금지, 같은 반복 3번 상한), 보고(확인함·워커 주장·확인 못 함)
  - 공통 규칙의 **캔버스에 그리고 묻기** (2026-11-18): 캔버스를 쓰는 방법이 지금 기능 그대로 적혀 있어요. 읽고 나서 그리기(`maestro canvas`, 접힌 영역은 그대로), 그리기(`maestro draw`, 좌표 대신 `layout`, 함께 묶이는 것에 같은 테두리 `color`, 시간·상황에 따라 달라지는 그림은 영역의 `steps` / `states`와 `maestro step` / `maestro state`, 관계는 `relation list` 먼저, `lint`의 `warn` 고치기), 묻기(`maestro ask`, 여러 개면 `--file`로 묶어 한 번에), 묶음(`"stack": true`), 파일 띄우기(`maestro show`), 답 받기(고친 질문이면 그것 기준), 적용하고 치우기(`maestro erase --question`), 사용자가 직접 놓은 질문(`by: user`)은 가리킬 때만 보기, 지우기(`maestro erase`). 명령의 정확한 형식은 `maestro --help`가 기준이라고 적어 뒀어요. "아키텍처 먼저"의 그리기 단계와 "계획 먼저"의 묻기 단계도 이 방법을 써요. **캔버스에 그리는 기능이 바뀌면 이 단락과 두 런북을 같은 변경에서 고쳐요**(브리프 `MAESTRO_HINT`, `maestro --help`의 `ROUTES`, 기능 문서와 함께)
  - 만드는 런북(나눠서 구현, 구현 → 리뷰 반복, 경쟁 실행, 아키텍처 먼저, 근본 원인 디버깅)의 합치기 단계는 `evidence-gate.md`를 거쳐요
  - 워커 쪽 규칙(보고 블록, 통과로 치지 않는 것, 승인)은 런북이 아니라 브리프(`MAESTRO_HINT`)와 페르소나에 있어요. 워커는 런북을 읽지 않아서예요. 보고 블록 형식은 → [워커 완료 메모](worker-done-notes.md)
  - 반복 상한(리뷰 3라운드, 검증 재시도 3번, 같은 증상 수정 3번)은 분석한 공개 문서들에서 합의된 숫자가 아니라 설계 선택이에요. 파일을 고쳐 바꿀 수 있어요
- **런북 고르기**: Lead 캔버스의 아일랜드(왼쪽 위 도구 막대)에 `런북` 버튼이 있어요. 누르면 아래로 목록이 펼쳐지고, 맨 위 `자동`(강조, 기본값: Lead가 요청에 맞게 고름) 아래에 런북들이 나와요. 하나를 고르면 버튼에 이름이 붙고, 아래 입력창에 `런북 · 이름` 칩이 생겨서 보내는 메시지마다 "[런북: 이름] 경로 를 읽고 이 절차를 따라."가 앞에 붙어요. 칩의 ×나 `자동`으로 되돌려요. 캔버스마다 앱이 켜져 있는 동안 기억해요(`PlaybookPanel`, Canvas `pickedBooks`).
- **런북**: 사이드바 `런북` → 시스템의 런북 보드. 문서와 똑같이 만들기·가져오기·열기·지우기를 해요(분류는 없어요). Lead는 시작할 때 안내문으로 런북 목록(제목과 경로)을 받고, 일을 나누기 전에 맞는 것을 읽고 따르라는 지시를 받아요.
- **어디서 보나**: 사이드바 바닥의 `문서`·`런북` 줄을 누르면 [시스템](../ui/system-tab.md)이 프로젝트처럼 열려요(카드마다 제목과 첫 줄). 에이전트 캔버스 도구 막대의 `문서` 버튼은 같은 목록을 도구 막대 바로 아래(왼쪽 위) 목록 패널로 띄워요. 처음엔 분류가 모두 접혀 있어요(`DocsList folded`).
- **목록**: 맨 위 `♟ 페르소나`, 그다음 분류 폴더가 이름순으로 나와요. 분류 줄을 누르면 접고 펼쳐요. 각 줄에 문서 수가 보여요.
- **만들기**: 맨 위 `+`는 새 분류, 분류 줄에 마우스를 올리면 나오는 `+`는 그 분류의 새 문서(페르소나 줄이면 새 페르소나)예요. 이름을 쓰고 Enter, Esc로 취소해요. 파일 이름은 영숫자·`-`·`_` 외 문자를 `-`로 바꿔요.
- **가져오기**: 분류 줄의 `⤓`로 바깥 마크다운을 골라 그 분류에 **복사해서** 넣어요(문서함에 더하는 동작). 이름이 겹치면 `-2`, `-3`을 붙여요.
- **열기·지우기**: 문서를 누르면 편집기 탭으로 열려요. 마우스를 올리면 나오는 `×`를 누르면 확인 창("'<제목>' 문서를 지울까요?", 빨간 [지우기])이 뜨고, 확인하면 지워요(그 문서를 참조하던 에이전트는 더 이상 열 수 없어요). → [메뉴와 확인 창](../ui/menus-and-dialogs.md)
- **고치기 전 확인**: 문서·페르소나·런북을 편집기에서 `편집`이나 `변경 비교`로 바꾸면 처음 한 번 확인 창이 떠요. 마크다운은 미리보기로 열리니 읽기만 할 때는 묻지 않아요. 앱이 켜져 있는 동안 파일마다 한 번만 물어요. [편집]을 누르면 고칠 수 있고, 취소하면 미리보기에 머물러요.
  - 런북: "모든 프로젝트의 Lead가 따르는 런북이에요" / 고친 절차는 Lead가 다음에 이 런북을 읽을 때부터 따라요
  - 페르소나: "모든 프로젝트가 같이 쓰는 페르소나예요" / 이 역할을 맡은 에이전트는 다음 시작부터 고친 내용을 따라요
  - 문서: "모든 프로젝트가 같이 쓰는 문서예요" / 이 문서를 참조하는 에이전트는 모두 고친 내용을 읽어요
  - 기본 제공 파일이면 "기본 파일이라 기본값으로 되돌릴 수 있어요" 줄이 붙어요.
- **기본값으로 되돌리기**: 기본 제공 파일을 Maestro가 넣어 둔 글로 되돌려요. 사용자가 만들거나 가져온 파일은 기본 글이 없어서 대상이 아니에요.
  - 파일 하나: 기본 제공 파일이 넣어 둔 글과 다르면 편집기 머리줄에 `기본값으로` 버튼이 보여요. 누르면 확인 창("기본값으로 되돌릴까요?", 빨간 [되돌리기]) 뒤에 바꿔요. 저장하지 않은 편집도 사라져요.
  - 보드 전체: [시스템](../ui/system-tab.md)의 문서·런북 보드 위쪽 `기본값으로`. 넣어 둔 글과 다른 기본 파일과 지운 기본 파일을 목록으로 보여 주고(확인 창 "기본 런북을 기본값으로 되돌릴까요?" 또는 "기본 문서를…", 빨간 [되돌리기]), 확인하면 고친 것은 넣어 둔 글로 바꾸고 지운 것은 다시 만들어요. 사용자가 만든 파일은 그대로 남아요. 문서 보드는 페르소나와 분류 폴더, 런북 보드는 런북만 다뤄요. 바꿀 것이 없으면 버튼이 흐리게 꺼져 있어요(툴팁 "모두 기본값이에요").
  - 기본값은 지금 앱에 들어 있는 판이에요. 지문을 적기 전(2026-11-20 전)에 예전 앱이 깔아 둔 파일은 고친 적이 없어도 지금 판과 다르면 대상에 들어가요. 한 번 되돌리면 지문이 적혀서, 그다음 판부터는 손대지 않는 한 저절로 바뀌어요.
  - 편집기에서 저장하거나 되돌리면 같은 창의 문서·런북 목록이 다시 읽혀요(제목, 첫 줄, 버튼 상태).
- **참조로 쓰기**: 문서를 캔버스로 끌면 마크다운 블록이 생기고, 블록을 에이전트에 이으면 참조가 돼요. 원본 파일을 가리키므로 문서를 고치면 참조하는 모든 에이전트가 고친 내용을 읽어요.
- 참조 연결 방법은 세 가지예요.
  - 캔버스에서 마크다운 블록과 에이전트를 선으로 잇기
  - 프로젝트 캔버스 카드의 `+`/`+N` 버튼 → `RefPicker`에서 체크(문서 목록과, 파일 트리에서 끌어온 프로젝트 파일)
  - `maestro ref add --path … [--to …]`
- 카드에는 연결된 페르소나가 `♟ <제목>`, 다른 문서가 `≡ <제목>` 칩으로 보여요.
- 실행 중인 에이전트에 페르소나를 연결하거나 해제하면 바로 `[Maestro] 이 워크트리의 페르소나가 '<제목>'(으)로 정해졌어요…` 또는 `…해제됐어요…` 메시지가 입력창으로 보내져요.

## 구현

- 페르소나(`library.rs`):
  - `personas_dir(home)` = `~/.maestro/personas`.
  - 기본 페르소나 파일은 아래 "기본 제공"의 `seed(home)`가 써요.
  - `create_persona(home, name)`: 영숫자·`-`·`_` 외 문자는 `-`로 바꾼 `<file>.md`를 만들고 `# <name>` 제목과 안내 한 줄을 써요. 이름이 비면 `"페르소나 이름을 적어 주세요"`, 같은 파일이 있으면 `"같은 이름의 페르소나가 있어요"`. 명령 `persona_create`.
  - `is_persona(home, md)`: 경로가 페르소나 폴더 아래인지(대소문자·구분자 무시).
- 마크다운 목록:
  - `title_of(path)`: frontmatter를 건너뛴 첫 `# ` 제목, 없으면 파일 이름. 명령 `md_title`.
  - `scan(folder)`: 깊이 4, 최대 500개, `.`으로 시작하는 폴더·`node_modules`·`target` 제외, 경로순 정렬.
- 기본 제공(`library.rs`): `BUILTIN`(폴더, 파일 이름, `include_str!` 본문) 목록을 `seed(home)`가 앱 시작 `setup`에서 써요. 폴더마다 `.seeded`에 한 번 쓴 파일 이름을 적어 두고, 거기 없고 파일도 없을 때만 써요.
  - 지문: `print(text)`(FNV-1a 64비트, CRLF/LF 무시. 표준 해셔는 Rust 판마다 값이 바뀔 수 있어서 직접 셈). 폴더의 `.shipped`에 `이름<TAB>지문(16진수)` 줄로 둬요(`written`, `write_marks`). `seed`가 파일을 새로 쓸 때, `restore_default`·`restore_defaults`가 되돌릴 때 `remember`로 적어요.
  - `update_untouched(home)`: `seed` 끝(이름 바꾸기 뒤)에 돌아요. 파일 지문이 적힌 값과 같고 지금 판과 다르면 지금 판으로 쓰고 지문을 바꿔요. 파일이 이미 지금 판이면 지문만 적어요. 적힌 값과 다르거나 적힌 것이 없으면 건드리지 않고, 없는 파일은 다시 만들지 않아요. 테스트: `untouched_built_ins_take_the_new_text`
- 문서 폴더: `docs_dir(home)` = `~/.maestro/library`. 런북: `playbooks_dir(home)` = `~/.maestro/playbooks`, `playbooks(home)`(명령 `playbook_list`). Lead 브리프(`agent::system_brief`)에 `## Runbooks` 목록이 붙어요. `all(home)`이 페르소나 폴더 + 분류 폴더(이름순)를 `LibFolder`로 돌려줘요.
- 쓰기는 `managed()`가 허락한 폴더(페르소나 폴더, 런북 폴더, 또는 문서 폴더 바로 아래 분류)에서만 해요: `create_doc`(명령 `docs_create`), `import_docs`(`docs_import`, 복사), `delete_doc`(`docs_delete`), `create_category`(`docs_category`). 테스트: `docs_live_only_in_managed_folders`.
- 기본값(`library.rs`): `shipped(home, path)`가 경로로 `BUILTIN` 본문을 찾아요(대소문자·구분자 무시, 없으면 사용자가 만든 파일). 비교는 줄바꿈(CRLF/LF)을 무시해요(`same_text`).
  - `default_state(home, path)` → `"none"`(사용자 파일) / `"same"` / `"edited"`(명령 `docs_default_state`)
  - `restore_default(home, path)`: 파일 하나를 본문으로 덮어써요. 사용자 파일이면 `"Maestro 기본 파일이 아니에요"`(명령 `docs_restore`)
  - `defaults_off(home, books)`: 한 보드에서 본문과 다르거나 없는 기본 파일을 `폴더/파일`(페르소나, 분류 이름, 런북)로 돌려줘요(명령 `docs_defaults_off`)
  - `restore_defaults(home, books)`: 그 파일들을 다시 써요. 지운 것은 폴더까지 다시 만들고, 쓴 개수를 돌려줘요(명령 `docs_restore_all`)
  - 테스트: `built_in_files_go_back_to_what_ships`
- 고치기 전 확인과 버튼(프런트엔드):
  - `sharedDocs.ts`: `sharedKind(path)`가 경로에 `/.maestro/playbooks/`·`/personas/`·`/library/`가 있는지로 런북·페르소나·문서를 가려요. `okToEdit(path, kind, builtin)`이 확인 창을 띄우고, 확인한 파일을 모듈의 `warned` 집합에 넣어 다시 묻지 않아요. `docsChanged()`/`onDocsChanged(f)`는 창 안의 `maestro:docs-changed` 이벤트예요.
  - `CodeView.tsx`: `setMode`가 미리보기가 아닌 모드로 갈 때 `okToEdit`를 기다려요. 읽기·저장 뒤에 `docs_default_state`로 `builtin`을 갱신하고, `"edited"`면 `기본값으로`(`.cv-reset`)를 보여요. `reset`은 자동 저장·초안 타이머를 멈추고 `docs_restore` 뒤 `load()`로 다시 읽어요.
  - `LibraryPanel.tsx` `useDocs`: 목록과 함께 `docs_defaults_off`를 읽어 `off`에 두고, `onDocsChanged`로 다시 읽어요. `resetAll`은 누를 때 목록을 새로 읽어 확인 창에 보여 줘요. 버튼은 `Board` 머리 막대에만 있어요(캔버스의 문서 패널에는 없어요).
- 예전의 프로젝트별 보관함 등록(`<project_dir>/library.json`, `library_set`)은 없앴어요. 남아 있는 파일은 읽지 않아요. 이미 걸린 참조는 경로라서 그대로 동작해요.
- `library_list()` → `library_folders()` → `library::all()`. `maestro library list`도 같은 함수예요. 화면은 LibraryPanel.tsx의 `useDocs`(읽기·만들기·가져오기·지우기)를 캔버스 패널의 `DocsList`와 시스템의 `SystemDashboard`가 같이 써요. `MdFile.summary`는 본문 첫 줄(frontmatter·제목·코드 울타리 제외, 140자)이에요.
- 참조 저장: `AgentMeta.refs: Vec<String>`.
  - `set_ref(project_root, worktree, md, on)` → `set_reference()` → `set_ref_meta()`. 대소문자 무시로 중복을 막고 `/` 경로로 저장해요.
  - `worktree`가 빈 문자열이고 `on=false`면 프로젝트의 모든 에이전트에서 그 경로를 빼요(캔버스에서 마지막 블록을 지웠을 때).
  - 페르소나이고 대상 에이전트가 실행 중이면 별도 스레드에서 `wait_ready()` 후 페르소나 본문을 포함한 메시지를 `send()`해요.
- `WorktreeInfo`: `worktree_infos()`가 `refs`를 `is_persona`로 나눠 `personas`(제목 목록)와 `docs`(제목 목록)를 채워요. `refs`(경로)도 그대로 나가요.
- 에이전트에 전달: `agent::system_brief(home, meta)`가 `refs`를 나눠
  - 페르소나마다 `## Your persona (assigned in Maestro; follow it)` 아래 파일 본문 전체
  - 나머지는 `## Reference documents linked to you (read them before starting work)` 아래 `- <제목> (<경로>)` 목록
  - 을 붙여요. 이 브리프는 `Agent::spawn`에서 Claude는 `<meta>.brief.md`로 써서 `--append-system-prompt-file`로, Antigravity는 `<meta>.brief/AGENTS.md`로 써서 `--add-dir`로 넘겨요. 테스트: `brief_carries_persona_and_references`.
- `maestro whoami`도 `references`를 보여 줘요.

## 제약과 알려진 문제

- 문서 본문(페르소나 제외)은 브리프에 넣지 않고 경로만 줘요. 에이전트가 직접 읽어야 해요.
- 브리프는 에이전트가 시작할 때만 만들어져요. 실행 중에 문서 참조를 바꾸면 페르소나만 즉시 메시지로 알리고, 일반 문서는 다음 시작 때 반영돼요.
- 브리프는 Claude Code에 `--append-system-prompt-file`로, Antigravity에는 `--add-dir`로 넘긴 규칙 폴더(`<meta>.brief/AGENTS.md`)로 가요. 둘 다 시작할 때 페르소나·참조를 받아요. 실행 중 페르소나 메시지는 어댑터와 상관없이 보내져요.
- `scan` 한도(깊이 4, 500개)를 넘는 파일은 목록에 안 나와요.
- 페르소나 파일을 지우는 UI는 없어요.
- 기본 제공 파일을 개정하면 손대지 않은 파일은 다음 시작 때 새 판이 돼요. 고친 파일은 저절로 바뀌지 않아서, 개정판을 받으려면 `기본값으로`를 눌러야 하고 고친 내용은 사라져요(고친 것과 새 판을 합쳐 주지 않아요). 지문을 적기 전(2026-11-20 전)에 깔린 파일도 고친 파일처럼 다뤄요. 고쳤다가 기본 글과 똑같이 되돌려 놓은 파일은 손대지 않은 파일로 쳐요.
- 되돌리기 전에 지금 내용을 따로 보관하지 않아요. 확인 창으로만 막아요.
- 고치기 전 확인은 앱의 편집기에서만 떠요. 에이전트가 파일을 직접 고치거나 바깥 편집기로 고치면 묻지 않아요. 앱을 다시 켜면 다시 물어요.
- 목록을 다시 읽게 하는 이벤트는 창 안에서만 돌아요. 다른 창(새 창으로 옮긴 묶음)의 보드는 ↻로 다시 읽어야 해요.
- 앱에서 확인하지 않았어요(확인 창, 버튼 위치, 되돌린 뒤 편집기 다시 읽기).
- 런북·페르소나의 규칙은 프롬프트 글이라 지키는지 앱이 강제하지 않아요. 앱이 막는 것은 명령 가드(병합·푸시·파괴적 git)와 병합 승인 카드뿐이에요.
