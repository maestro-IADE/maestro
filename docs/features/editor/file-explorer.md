# 오른쪽 패널

## 요약

오른쪽 패널에는 "파일"과 "변경" 두 탭이 있어요. 지금 고른 에이전트의 워크트리(고르지 않았으면 프로젝트 폴더)의 파일 트리와 git 변경 목록을 보여 줘요. 머리(32px)는 사이드바 머리·탭 막대와 한 높이라 세 패널 위 선이 일직선이에요. 변경 탭에는 바뀐 파일 수가 붙고, 고른 탭은 앱을 다시 켜도 남아요. 변경 목록은 에이전트가 작업하는 동안 4초마다 다시 읽어요. 파일을 누르면 편집기가, 변경된 파일을 누르면 HEAD와 비교하는 diff 뷰가 열려요.

## 동작

**머리(32px)**
- 왼쪽 탭 둘: `Files` 14 + "파일", `GitCompare` 14 + "변경" + 바뀐 파일 수(11px, 흐린 숫자, 0이면 숨김). 고르지 않은 탭은 흐린 글자, 마우스를 올리면 진한 글자, 고른 탭은 진한 글자 + 탭 가운데 절반 폭의 2px 밑줄이에요.
- 오른쪽 24×24 버튼 하나: 파일 탭이면 `ListCollapse` "모두 접기"(펼친 폴더를 모두 닫아요), 변경 탭이면 `RotateCw` "새로고침".
- 고른 탭은 저장돼요(`maestro.rightTab`). 예전처럼 매번 파일 탭으로 돌아가지 않아서, 변경을 자주 보는 사람은 행 한 번으로 비교가 열려요.

**출처 줄(24px)**
- 목록이 어디 것인지 보여요: 에이전트가 열려 있으면 `GitBranch` 12 + 브랜치 이름(11px 고정폭, 흐린 글자), 아니면 `Folder` 12 + "<프로젝트> · 원본". 마우스를 올리면 폴더 경로가 떠요.

**파일 탭**
- 행 높이 24, 12px. 들여쓰기 `8 + 깊이×12`, 쉐브론 자리 12 → 4 → 아이콘 14 → 6 → 이름.
- 폴더를 누르면 펼쳐져요. 파일을 누르면 미리보기 탭으로, 더블클릭하면 고정 탭으로 편집기가 열려요.
- 아이콘으로 파일, 닫힌 폴더, 열린 폴더를 구분해요.
- 지금 편집기에 열린 파일은 선택 면이 깔려요. 선택·hover 면은 양옆 4px 안쪽, 반경 6이에요.
- 긴 이름은 "…"로 자르고, 마우스를 올리면 전체 경로가 보여요.
- `.git`은 숨겨요. 폴더가 먼저 오고, 이름은 대소문자를 무시하고 정렬해요.
- 변경 탭을 보고 돌아와도 펼친 폴더가 그대로예요(두 탭 모두 그려 두고 하나만 보여요). 다른 에이전트로 바꾸거나 "모두 접기"를 누르면 처음 상태로 돌아가요.

**변경 탭**
- 행 높이 24(안쪽 0 8 0 12): 상태 글자 상자 16(10px 고정폭 600) → 6 → 파일 이름(12px 진한 글자) → 6 → 폴더(11px 흐린 글자, 넘치면 말줄임). 이름과 폴더는 따로 그려서 긴 경로에서도 이름이 먼저 보여요. 마우스를 올리면 전체 경로가 떠요.
- 상태 글자: `M` 수정·`R` 이름 바뀜·`T` 형식 바뀜(경고색), `A` 추가·`C` 복사·`U` 추적 안 됨(초록), `D` 삭제(빨강), `!` 충돌(오류색). 글자 위 툴팁이 그 뜻이에요.
- 행을 누르면 HEAD와 비교(미리보기 탭), 더블클릭하면 고정 탭이에요.
- 마우스를 올리거나 행 안에 포커스가 있으면 오른쪽 끝에 20×20 버튼이 행과 같은 면으로 글 끝을 덮어요(글 폭은 그대로). 포커스만 있을 때도 행과 덮개가 함께 hover 면이에요: `GitCompare` "비교", `FileText` "열기"(비교 없이 편집기로. 지운 파일에는 없어요).
- 바뀐 파일이 없으면 가운데에 "바뀐 파일이 없어요". 읽기에 실패하면 목록 위에 오류 글이 보여요.
- **다시 읽는 때**
  - 에이전트 상태가 바뀔 때(작업이 끝났거나 시작했을 때). 그래서 작업이 끝나면 한 번 더 읽어요.
  - 창이 포커스를 받을 때(다른 프로그램에서 파일을 고치고 돌아왔을 때).
  - 변경 탭이 보이고 그 에이전트가 작업 중이면 4초마다.
  - 다른 에이전트로 바꾸거나 오른쪽 패널을 다시 보일 때, `RotateCw`를 누를 때.
  - 앞 읽기가 아직 안 끝났으면 4초 읽기는 건너뛰어요. 그 사이에 들어온 다른 읽기(상태 변경, 포커스, 새로고침)는 앞 읽기가 끝난 뒤 한 번만 해요.
  - 패널을 숨겨 두면 읽지 않아요.
- 개수는 파일 탭을 보고 있어도 머리에 보여요(4초 읽기만 변경 탭이 보일 때예요).
- 파일과 폴더를 끌어서 첨부할 수 있어요. → [드래그 첨부](drag-attach.md)

**문서·플레이북**
- 포커스된 묶음이 [시스템](../ui/system-tab.md)(문서·플레이북)을 보고 있으면 가운데에 "문서와 플레이북에는 파일 트리가 없어요"가 보여요. 머리 자리(32px)는 비워 둬서 위 선은 그대로 이어져요.

## 구현

- `RightPanel({ visible })`(RightPanel.tsx). `visible`은 App.tsx의 `showRight`(오른쪽 패널 보임)예요. 탭은 `useState(readTab)` + `localStorage`(`RIGHT_TAB_KEY`, 읽기·쓰기 모두 try/catch).
- `useChanges(path, status, visible, onTab)`: 변경 목록 상태(`files`, `err`)와 `refresh(queue)`.
  - 진행 중 표시 `inflight`(그 경로)와 `again` 플래그. `refresh(false)`(4초 읽기)는 진행 중이면 그냥 건너뛰고, `refresh(true)`(그 밖)는 `again`을 세워 끝난 뒤 한 번 더 읽어요. 경로가 바뀌면 옛 답은 버려요.
  - 효과: 경로가 바뀌면 목록 비움 / `[path, status, visible]`이 바뀌면 보일 때 한 번 / 보이는 동안 `window` `focus` 이벤트 / `poll = visible && onTab && status === "RUNNING"`일 때만 `setInterval` 하나(4000ms).
- `Tree`, `TreeItem`, `TreeIcon`: 파일 트리. 두 탭 본문(`.rp-body`)을 모두 그리고 `hidden`으로 하나만 보여요. "모두 접기"는 트리의 `key`를 바꿔 다시 그려요.
- `Changes`: 변경 행. 순수 함수는 `src/rightPanelModel.ts`:
  - `splitPath(rel)` → `{ name, dir }`(백슬래시를 `/`로, 끝 `/` 뗌).
  - `changeCode(xy)` → `{ letter, kind: "add" | "mod" | "del" | "conflict", label }`. porcelain 두 글자에서 `??` = U, 충돌(`U`가 있거나 `AA`·`DD`) = `!`, 그 밖은 앞 글자(인덱스 쪽 우선, `AM` = A).
  - `parseRightTab(v)`: `"changes"`만 변경 탭, 나머지는 파일 탭.
  - 테스트: `scripts/right-panel-check.ts`(`npm test`).
- CSS: `.rp-head`(높이 `var(--h-bar)`), `.rp-tab[aria-selected]::after`(밑줄), `.rp-count`, `.rp-act`, `.rp-source`(높이 `var(--h-row)`), `.rp-empty`, `.tree-row`·`.change-row`(높이 `var(--h-row)`, `margin: 0 4px`, 반경 `--mae-r-item`), `.chg-code[data-kind]`, `.chg-name`, `.chg-dir`, 덮개 `.row-acts`(`position: absolute; right: 4px`, 행의 지금 면, `opacity` 0→1).
- `list_dir(path)`: 폴더 항목을 정렬해서 돌려줘요.
- `git_status(worktree_path)`: `worktree::status` → `git status --porcelain=v1 -z -uall`. `-z`라 한글·공백·따옴표가 든 이름도 따옴표나 `í…` 같은 이스케이프 없이 그대로 와요(`core.quotePath` 설정과 상관없음). 이름 바뀐 파일은 새 이름을 써요.
- 아이콘 경로는 `TREE_ICONS`(Lucide file / folder / folder-open)예요. 드래그 칩도 이 경로를 써요.

## 제약과 알려진 문제

- 파일 트리는 자동으로 새로고침되지 않아요. 에이전트가 새 파일을 만들면 폴더를 다시 접었다 펴야 보여요(변경 탭에는 4초 안에 보여요).
- 이름 바뀐 파일의 diff는 HEAD 쪽을 새 이름으로 찾아서 새 파일처럼 보여요.
- 큰 저장소에서는 `git status -uall`이 무거워요. 그래서 4초 읽기는 변경 탭이 보이고, 그 에이전트가 작업 중이고, 앞 읽기가 끝났을 때만 해요. 프로젝트 폴더(에이전트를 고르지 않음)에는 작업 중 상태가 없어서 4초 읽기를 하지 않아요.
- 창 포커스 읽기는 파일 탭을 보고 있어도 해요(머리 개수 때문). 패널을 숨기면 하지 않아요.
- 앱 화면은 타입 검사만 했고, 실제 화면은 사용자가 확인해요.

## 결정 기록

- 2026-11-13 (리뷰 수정): 변경 행에 키보드 포커스만 있을 때도 행과 덮개에 hover 면을 칠해요. 덮개는 `background: inherit`인데 행이 `:focus-within`에서 면이 없어, Tab으로 [비교]·[열기]에 오면 버튼이 투명한 면으로 파일 이름과 폴더 글자 위에 그려졌어요.
- 2026-11-13 (UI 구조 재구성 단계 10): 머리를 32px로 낮추고 탭에 아이콘과 바뀐 파일 수를 붙였어요. 출처(브랜치/원본)는 머리 안 두 번째 줄이던 것을 24px 출처 줄로 따로 뺐어요. 세 패널 머리가 같은 높이가 되고, 변경을 열지 않아도 몇 개 바뀌었는지 보여요.
- 같은 날: 변경 행을 전체 경로 한 덩어리에서 이름 / 폴더 두 요소로 나눴어요. 좁은 패널에서 `src/features/…/App.tsx`의 이름이 잘려 보이지 않던 문제예요.
- 같은 날: 탭을 기억해요(`maestro.rightTab`). 매번 파일 탭으로 돌아가서 변경 비교가 두 번 누름이던 것(흐름 F7)이 한 번이 돼요.
- 같은 날: 변경 목록을 작업 중 4초마다 다시 읽어요. 예전에는 상태가 바뀔 때만 읽어서 긴 작업 동안 목록이 낡아 있었어요. 비용 때문에 "보이는 변경 탭 + 작업 중 + 앞 읽기 끝남" 세 조건을 모두 지켜요. 숨긴 패널은 읽지 않아요.
- 같은 날: 탭 이름 "변경사항" → "변경"(용어 표). 개수 "N개 파일 변경" 줄은 머리 개수로 옮기고 없앴어요.
- 같은 날: 시스템 탭에서 빈 패널 대신 안내 한 줄을 보여요. 빈 패널은 고장처럼 보였어요.
- 같은 날(계획에 없던 것): 상태 글자에 `U`(추적 안 됨, 예전 `??`)와 `!`(충돌)를 정했어요. 16px 상자에 두 글자가 들어가지 않아서예요. 덮개의 "열기"는 지운 파일에서 숨겨요(열 파일이 없어요).
