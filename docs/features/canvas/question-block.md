# 질문 블록

## 요약

에이전트가 사람의 결정이나 입력이 필요할 때 `maestro ask`로 자기 캔버스에 질문 블록을 놓아요. 보기가 있으면 객관식, 없으면 주관식이에요. 사람이 블록에서 답하면 그 답이 `[maestro] 질문 … 답했어요` 메모로 그 에이전트의 입력에 들어가요. 답한 블록은 고른 것과 고르지 않은 보기를 함께 남겨서 그대로 결정 기록이 돼요. 결정 게이트를 따로 만들지 않고, 결정은 "객관식 질문에 답한 기록"으로 다뤄요. 질문 블록은 하나이고, 쓰이는 흐름이 둘이에요. 보통의 흐름: 에이전트가 질문을 만들어 캔버스에 띄우고, 사람이 답하고, 에이전트가 답을 읽어 적용한 뒤 질문을 치워요(`maestro erase --question`). 다른 흐름: 사람이 블록을 직접 놓아요. 이 블록은 "에이전트가 읽을 것"이라는 기대 없이 시작해요. 답은 블록에 남기만 하고, 사람이 그 블록을 골라 에이전트에게 보라고 할 때 에이전트가 읽어요. 답하기 전에는 누구의 질문이든 고칠 수 있어요.

## 동작

**에이전트가 묻기**: `maestro ask --title 질문 [--choices "A|B|C"] [--multi true] [--other true] [--body 설명]`

| 옵션 | 뜻 |
|---|---|
| `--title` | 질문(필수) |
| `--choices` | `\|`로 나눈 보기 2~8개. 있으면 객관식, 없으면 주관식. 같은 보기 두 번, 보기 하나, 9개 이상은 오류 |
| `--multi true` | 여러 개 고르기(객관식만. 보기 없이 쓰면 오류) |
| `--other true` | 보기 옆에 "기타" 글칸(객관식만. 주관식에서는 무시) |
| `--body` | 질문 아래 작은 설명 |

- 답: `{ asked: <질문 id>, kind: "객관식"|"주관식", note }`. 질문은 그리기처럼 열린 캔버스에 바로 놓이고, 닫혀 있으면 캔버스를 열 때 놓여요.
- 브리프(`MAESTRO_HINT`)가 모든 에이전트에게 "결정이나 입력이 필요하면 긴 답 속에 묻지 말고 캔버스에 물어라, 물었다고 답에 말하고 그 답이 필요한 일은 기다려라"라고 알려요.

**질문 묶음 (여러 개를 한 번에 묻기)**: `maestro ask --file questions.json`. 질문이 2~10개일 때 써요(PRD를 쓰기 전에 여러 가지를 정해야 할 때처럼).
```json
{ "title": "시작 전에 정할 것",
  "questions": [
    { "title": "어떤 화면부터 만들까요?", "choices": ["로그인", "대시보드", "설정"] },
    { "title": "지원할 플랫폼을 골라 주세요", "choices": "Windows|macOS|Linux", "multi": true, "other": true },
    { "title": "첫 버전의 마감은 언제인가요?", "body": "대략이면 돼요" } ] }
```
- `title`은 묶음 이름(선택, 없으면 "질문 N개"). `questions`의 각 항목은 질문 하나와 같은 규칙이에요(`choices`는 목록이나 `A|B` 글). 목록만 줘도 돼요. 질문 하나, 11개 이상, 같은 질문 두 번, 질문 하나라도 규칙에 어긋나면 오류이고 아무것도 놓이지 않아요(오류는 "2번째 질문: …"처럼 몇 번째인지 말해요).
- 답: `{ asked: [질문 id…], set: <묶음 id>, kind: "묶음", note }`.
- 캔버스에는 **단계가 있는 영역 하나**로 놓여요(→ [영역](zones.md)). 질문마다 한 단계이고, 영역은 한 번에 질문 하나만 보여 줘요. 영역 머리의 `2 / 3`과 ◀ ▶로 앞뒤 질문을 오갈 수 있어요.
- 질문 블록의 화살표가 "다음"이 돼요. 누르면 그 답을 블록에 적어 두고(상태 "적어 둠", 아래에 `2 / 3`) 아직 답하지 않은 다음 질문으로 넘어가요. 적어 둔 답은 모두 보낼 때까지 고칠 수 있어요.
- 남은 질문이 지금 것 하나뿐이면 화살표가 "모두 보내기"예요(아래 글 `3 / 3 · 누르면 모두 보내요`). 누르면 답이 **메모 하나로** 에이전트에게 가고, 묶음의 모든 블록이 "✓ 답함"으로 잠겨요.
```
[maestro] 질문 3개에 사용자가 답했어요.
1. '어떤 화면부터 만들까요?' → 고른 것: 대시보드
2. '지원할 플랫폼을 골라 주세요' → 고른 것: Windows, macOS · 덧붙인 말: 리눅스는 나중에
3. '첫 버전의 마감은 언제인가요?' → 답: 다음 달 말
```
- 사람이 고친 질문은 그 줄에 `(사용자가 고친 질문. 설명: …. 보기: … | …)`가 붙어요.
- 치우기: `maestro erase --question <묶음 id>`(또는 묶음 이름)가 영역과 질문을 함께 지워요. 질문 하나만 지우면(`--question <질문 id>`) 그 질문의 단계도 빠지고, 마지막 질문이 지워지면 영역도 같이 사라져요. `erase --all true`는 묶음도 지워요.
- 묶음의 질문을 영역 밖으로 끌어내면 혼자 묻는 질문처럼 따로 답해요(묶음은 남은 질문만 보내요).

**단계가 있는 영역 안의 질문 하나**: 묶음이 아닌 질문이 단계 영역의 어떤 단계에만 있을 때(→ [영역](zones.md) "보이는 때"), 답하면 영역이 다음 단계로 넘어가요(다음 단계가 있을 때). 화살표가 "보내고 다음으로"를 함께 맡아요.

**사람이 고치기**: 아직 답하지 않은 질문은 더블클릭이나 우클릭 → "질문 편집…"으로 편집 창을 열어요. 에이전트가 물은 질문도 고칠 수 있어요.
- 편집 창: 질문(Enter로 닫기), 설명(선택), 보기(한 줄에 하나, 비우면 주관식, 같은 줄·빈 줄은 빠지고 8개까지), "여러 개 고르기"와 "기타 글칸"(보기가 있을 때만). 적는 대로 블록에 반영돼요.
- 에이전트의 질문을 고친 뒤 답하면, 에이전트가 물은 것과 달라졌으니 메모에 고친 질문·설명·모든 보기가 같이 가요:
```
[maestro] 사용자가 질문을 고쳐서 답했어요. 고친 질문: '어느 DB?'
설명: 로컬 개발용
보기: Postgres | SQLite
고른 것: SQLite
```

**채팅에 묻기**: 대화의 갈림길(어떻게 진행할지)은 캔버스가 아니라 채팅에 선택지로 물어요(`maestro ask --in chat`). 질문의 모양과 답 메모는 같고 놓이는 곳만 달라요. → [채팅 선택지](../agents/chat-choices.md)

**평소에는 묻지 않아요**: 캔버스 질문은 일이 사용자의 결정에 달려 있을 때 써요. 지나가며 확인하는 짧은 물음은 에이전트가 답 글에서 그냥 물어요. Maestro를 보통의 코딩 에이전트처럼 쓸 때는 질문 블록이 생기지 않는 것이 정상이에요(브리프가 그렇게 알려요).

**스킬을 따라 할 때**: 에이전트가 스킬이나 플러그인 명령(브레인스토밍, 설계 검토처럼 사용자에게 묻고 고르게 하는 것)을 따라 하는 중에도 일이 달린 질문은 캔버스에 올리라고 브리프와 기본 런북이 알려요(2026-11-18). 스킬이 하는 일 자체와 스킬의 짧은 물음은 그대로예요. 다만 앱이 질문을 가로채 바꾸는 것은 아니에요: 에이전트가 그 지침을 따라 `maestro ask`를 부를 때만 질문 블록이 돼요. 스킬이 에이전트의 내장 질문 도구를 직접 쓰게 하면 그 질문은 터미널(또는 채팅의 승인 카드 자리)에 나오고 캔버스에는 생기지 않아요.

**에이전트가 치우기**: 답을 적용한 에이전트는 `maestro erase --question <id>`로 그 질문 블록을 지워요(id는 `ask`의 답 `asked`와 `maestro canvas`의 `questions[].id`, 질문 글 그대로 써도 돼요). 브리프와 `ask`의 답이 이렇게 하라고 알려요. 캔버스에는 아직 기다리는 질문만 남아요. `erase --all true`는 질문 블록도 모두 지워요(답한 것, 답을 기다리는 것, 손으로 그린 것 모두). 답을 기다리던 질문은 답 없이 사라지고 메모도 가지 않아요: `erase`의 답 `erased.unanswered`가 그 수예요(손으로 그린 질문은 세지 않아요). 사용자는 Ctrl+Z로 되돌려요.

**사람이 직접 놓기**: 도구 막대의 질문 버튼(프롬프트 옆, `MessageCircleQuestion`), 또는 빈 곳 우클릭 → "질문 블록 추가"(우클릭한 자리에). 에이전트의 질문과 같은 블록이고, 시작이 달라요: 에이전트가 읽을 것이라는 기대가 없어요.
- 놓으면 편집 창이 바로 열려요.
- 블록 머리는 에이전트의 질문과 같은 "질문"이고, 상태 자리에 조용한 색으로 "직접 놓음"이 보여요. 기다리는 에이전트가 없어서 경고색 테두리는 없어요.
- 화살표 버튼을 누르면 답이 블록에 남아요. 에이전트에게 메모가 가지는 않아요. 질문이 비어 있으면 눌리지 않아요.
- **에이전트에게 보이기**: 블록을 고른 채 아래 입력창으로 말하면 선택 칩에 질문·보기·답이 같이 붙어 가요. 에이전트는 `maestro selection`으로도 같은 것을 읽어요(kind `question`, 직접 놓은 것은 `by: "user"`). 에이전트의 질문 블록도 같은 방법으로 가리킬 수 있어요.
- `maestro canvas`의 `questions`에는 `by: "user"`가 붙어 나와요. 브리프는 에이전트에게 "사용자가 직접 놓은 질문은 나에게 한 것이 아니니, 사용자가 가리킬 때만 보라"고 알려요.

**블록 모양**(폭 13칸 = 312px, 높이는 내용만큼)
- 머리: 물음표 아이콘, "질문", 오른쪽에 상태. 답을 기다리는 동안은 테두리와 상태 글이 경고색("답을 기다려요"), 답하면 조용한 "✓ 답함"(마우스를 올리면 답한 시각).
- 몸통: 질문(굵게), 설명(흐리게), 보기 버튼(하나 고르기는 동그라미, 여러 개는 네모 표시), 주관식이면 3줄 글칸, `--other`면 1줄 "기타" 글칸.
- 아래: 보내기 버튼은 글자가 아니라 오른쪽 화살표(→)가 든 둥근 버튼이에요(채팅 입력창의 보내기 버튼과 같은 모양, `composer-btn send`). 고른 것이나 적은 글이 있어야 눌려요. 글칸에서 Enter는 보내기, Shift+Enter는 줄바꿈. 여러 개 고르기면 "여러 개 고를 수 있어요"가 보여요. 보내지 못하면 오류가 그 자리에 떠요.
- 하나 고르기에서 고른 보기를 다시 누르면 고르기가 풀려요.
- 답한 뒤: 버튼과 글칸이 잠기고, 고른 보기는 강조, 고르지 않은 보기는 흐리게 남아요. 적은 글은 "기타: …"(주관식은 그대로)로 보여요. 다시 답하기는 없어요.

**답 전달**: 보내기 → `answer_question(owner, id, title, picked, text)` → 그 에이전트에게 메모. 메모는 워커 완료 메모와 같은 길(`control::tell`)이라, 에이전트가 꺼져 있거나 입력창이 아직 안 떴으면 보관했다가 뜰 때 붙여요(질문마다 하나, 키 `answer:<id>`).
```
[maestro] 질문 '어느 DB?'에 사용자가 답했어요.
고른 것: SQLite
덧붙인 말: 나중에 Postgres로 옮길 수 있게
```
주관식은 `답: …` 한 줄이에요. 고른 것은 보기 순서대로예요(누른 순서가 아니라).

**캔버스에서**: 질문 블록은 캔버스 파일에 저장돼요(질문, 보기, 답). 우클릭 메뉴는 "지우기"예요. 연결점은 없어요(선으로 잇지 않아요). 영역 안에 끌어 놓으면 그 영역에 속하고, 그 영역을 접으면 칩이 "질문 N"과 경고색 테두리로 기다리는 질문을 알려요(→ [영역](zones.md)). `maestro canvas`의 `questions`에 `{id, title, choices, multi, answer, area, box}`로 나와요(`answer`는 답 전에는 `null`, 답한 뒤 `{picked, text?, at}`, `area`는 속한 영역 이름).

## 구현

- CLI: `control.rs` `"ask"` 경로. `question(id, title, body, choices, multi, other)`가 검사하고 `{id, title, body?, choices, multi, other}`를 만들어요. id는 `q_<ms>_<순번>`. 그리기 큐(`state.drawings`)에 `{ ask }`로 넣고 `maestro://draw`를 보내요.
- 캔버스: 그리기 큐를 받는 곳(`Canvas.tsx`)이 `{ ask }`를 `applyAsk(q, scope, nodes)`(drawing.ts)로 놓아요. 자리는 새 그림과 같은 곳(캔버스의 첫 빈 자리: 위부터, 왼쪽부터. → [구조 그리기](structure-drawing.md) "배치 규칙"). 같은 id는 한 번만.
- 노드: `question_block`(`QuestionNode`, types.ts `QuestionData`: `qid`, `owner`(이 캔버스의 에이전트 폴더), `mine?`(사람이 직접 놓음), `edited?`(에이전트의 질문을 사람이 고침), `title`, `body?`, `choices?`, `multi?`, `other?`, `answer?`). 컴포넌트는 `nodes/QuestionBlock.tsx`, 스타일은 styles.css `.node-question`, `.q-*`.
- 고치기와 직접 놓기: `Canvas.tsx`의 `qEditing`이 답하지 않은 질문이면 누구 것이든 `QuestionEditor`(QuestionBlock.tsx)를 열어요. 에이전트의 질문을 고치면 `edited: true`를 같이 적어요. `addQuestion(at?)`은 id `q_<ms>`, `mine: true`인 블록을 놓고 편집 창을 열어요. 보기 줄 정리는 `parseChoices`.
- 답: `QuestionBlock`의 `send`가 `mine`이면 `answer`만 적고, 아니면 `ipc.answerQuestion`을 불러요. `main.rs` `answer_question` 명령(`edited`, `body`, `choices`를 함께 받아 고친 질문이면 `control::Edited`로 넘겨요)(입력창을 기다릴 수 있어 `spawn_blocking`) → `control::answer_question` → `locate`로 프로젝트를 찾고 `tell`. 메모 글은 `answer_note`. 개발용 시험 캔버스의 질문은 보내지 않고 시험 화면에 메모를 보여 줘요(→ [개발용 시험](../ui/dev-tools.md)).
- 읽기: `canvas.rs` `nodes_of`가 `question_block`을 kind `question`으로 읽고, `read`가 `questions`에 모아요(`others`에는 넣지 않아요). `mine`이면 `by: "user"`를 붙여요.
- 선택으로 보이기: `Canvas.tsx`의 `picked`가 고른 질문 블록을 `Picked` kind `question`(`title`, `body?`, `choices`, `multi?`, `answer?`, `by?`)으로 넣어요. 입력창 앞머리 글은 `AgentNode.tsx` `pickedLine`(질문, 설명, 보기, 답 또는 "답: 아직 없음"), 백엔드는 다른 선택처럼 그대로 `maestro selection`에 돌려줘요.
- 치우기: `control.rs` `erasing`이 `--question`(과 `--file`의 `questions`)을 저장된 캔버스의 질문 블록과 맞춰(id 또는 질문 글) id 목록으로 바꾸고, `drawing.ts` `applyErase`가 `Erase.questions`의 블록을 지워요. 없는 질문이면 오류예요.
- 묶음(백엔드): `control.rs` `"ask"` 경로가 `--file`이 있으면 `question_set(spec, fresh)`으로 검사해 `{id: "qs_…", title?, questions: [...]}`를 만들고 그리기 큐에 `{ ask_set }`으로 넣어요(`SET_MAX = 10`). 답은 `main.rs` `answer_questions(owner, set, answers)` → `control::answer_set` → `answers_note`(번호 줄) → `tell`(키 `answers:<묶음 id>`). 하나라도 비면 "N번째 질문에 아직 답하지 않았어요"로 거절해요.
- 묶음(화면): `drawing.ts` `applyAskSet(set, owner, nodes)`가 영역(`zone_<묶음 id>`, `mode: "step"`, 질문마다 이름 없는 단계 `ph_<질문 id>`, `qset: 묶음 id`)과 그 안의 질문 블록들(`set: 묶음 id`, `when: [자기 단계]`, 모두 같은 자리)을 놓아요. `QuestionBlock`은 부모 영역의 `qset`이 자기 `set`과 같으면 묶음으로 동작해요: 고른 것을 `draft`에 적어 두고(`keep`), `sendSet`이 남은 질문이 있으면 `goPhase`로 그 단계로 가고, 없으면 `ipc.answerQuestions`를 부른 뒤 모든 블록에 `answer`를 적어요. 단계 영역 안의 혼자인 질문은 답한 뒤 `goPhase(…, "next")`.
- 묶음 지우기: `erasing`이 `--question`을 묶음 id나 묶음 이름(그 이름의 질문이 없을 때)으로도 받아 `questions`(묶음의 질문 id들)와 `sets`를 돌려주고, `applyErase`가 `Erase.sets`의 영역을 지워요. 묶음 영역이 지워지면 그 질문도, 마지막 질문이 지워지면 영역도 같이 가요. 질문 하나만 지워지면 `removePhase`로 그 단계를 빼요.
- 시험: `control.rs` `question_checks_its_choices`, `answer_note_says_what_was_picked`, `question_sets_are_checked_and_answered_in_one_note`, `erasing_checks_names_against_the_canvas`, `canvas.rs` `read_gives_questions_with_their_answers`, `agent.rs` 브리프 시험, `scripts/dev-steps-check.ts`(시험 목록의 묶음 단계). 화면 쪽은 타입 검사와 개발용 시험(→ [개발용 시험](../ui/dev-tools.md)).

## 제약과 알려진 문제

- 화면 확인(2026-11-18, 개발 빌드를 스크립트로 조작): 질문 블록 세 가지와 질문 묶음이 놓이는 것, 묶음에서 고르면 "적어 둠", 화살표로 다음 질문, 머리의 ◀로 돌아가도 고른 것이 남는 것, 마지막에 "모두 보내기"와 번호 줄 메모 하나, 질문 하나 답하기와 그 메모, `erase --question`으로 질문과 묶음이 지워지는 것을 확인했어요. 확인하지 못한 것: 사람이 고친 질문의 메모(`edited`), 단계 영역 안의 혼자인 질문이 답한 뒤 다음 단계로 넘기는 것, 진짜 에이전트가 메모를 받아 이어 가는 것.
- 캔버스를 열지 않으면 질문을 볼 곳이 없어요. "확인할 일"(위 막대의 알림)이나 사이드바에 기다리는 질문 표시는 아직 없어요. 에이전트가 답에 "캔버스에 물었다"고 말하는 것이 지금의 알림이에요.
- 열리지 않은 캔버스의 질문은 앱 메모리의 그리기 큐에 있어서, 캔버스를 열기 전에 앱을 끄면 사라져요(그리기와 같음).
- 답을 고치거나 다시 보낼 수 없어요. 답하기 전에 질문 블록을 지우면 에이전트에게 알리지 않아요.
- 에이전트가 질문을 치우는 것은 브리프의 지시예요. 치우지 않는 에이전트도 있을 수 있고, 그러면 답한 블록이 남아요(사람이 지우면 돼요).
- `erase --question`은 저장된 캔버스를 보기 때문에, 캔버스가 닫혀 있어 아직 놓이지 않은 질문은 지우지 못해요(오류로 알려 줘요).
- 묶음은 모든 질문에 답해야 보낼 수 있어요(건너뛰고 보내기는 없어요. 주관식에 "모름"이라고 적는 식으로 넘겨요).
- 묶음의 질문은 모두 같은 자리에 겹쳐 있고 단계로 하나씩 보여요. 영역 편집에서 그 영역의 "보이는 때"를 "늘"로 바꾸면 질문이 한자리에 겹쳐 보여요(되돌리기로 돌아가요).
- 묶음의 영역은 지금 보이는 질문에 맞아요: 질문을 넘길 때마다 그 질문의 높이로 다시 맞춰져요(→ [영역](zones.md) "크기").

- 2026-11-18 (사용자 요청 "prd 스킬처럼 질문 여러개 줄 수도 있는데", "1번 문제의 인풋 블럭은 영역블럭 step1에 존재하고 다음 질문은 다음 스탭으로 넘어가게 하자"): 질문 묶음을 만들었어요. 새 블록 종류를 만들지 않고 "단계가 있는 영역 + 질문 블록 여러 개"로 했어요. 영역의 단계가 이미 "한 번에 하나만 보이기"와 "앞뒤로 가기"를 갖고 있어서예요. 답은 하나씩이 아니라 한 번에 보내요: 에이전트가 답 일부만 보고 일을 시작하지 않게, 그리고 메모가 여러 번 끼어들지 않게 하려는 것이에요. 화살표는 "마지막 질문"이 아니라 "남은 질문이 이것뿐일 때" 모두 보내기가 돼요. 머리의 ◀ ▶로 건너뛰며 답해도 빠진 질문으로 데려다주기 위해서예요.

"보내지 않는다"가 아니라 "기대 없이 시작하고, 사람이 가리키면 읽는다"예요.
- 2026-11-18 (사용자 정정): 사람이 만든 질문을 "에이전트에게 보내는 입력"으로 다룬 것은 사용자의 뜻이 아니었어요("내가 에이전트한테 인풋을 제공하는 게 아니야", "에이전트가 항상 선택지를 만들어주는 거야"). 질문 블록은 에이전트가 캔버스에 그리는 것의 하나이고, 사람은 캔버스를 손댈 수 있으니 고치거나 시험 삼아 놓아 볼 수 있을 뿐이에요. 그래서 "내 질문"과 "에이전트에게 보내요" 표시를 없애고, 직접 놓은 블록의 답은 보내지 않게 했어요(블록에만 남음). 에이전트의 질문은 답하기 전에 고칠 수 있게 열었고, 고친 질문의 답에는 고친 내용이 함께 가요. 아래 2026-11-17의 "구조 있는 입력" 결정은 이것으로 바뀌었어요.
