# 캔버스 조작

## 요약

캔버스 위에 떠 있는 막대는 둘이에요. 왼쪽 위의 세로 도구 막대(어도비 일러스트레이터처럼 아이콘만 세로로, 프로젝트 지도와 에이전트 캔버스 모두)와 왼쪽 아래 줌 바(− / 배율 / + / 전체 보기)예요. 도구 막대는 두께 44px, 버튼 36px, 아이콘 18px로 창 위 막대(36px)보다 한 단계 커요(`--h-canvas-tool`, `--icon-btn-canvas`). 줌 바는 창 위 막대와 같은 36px이에요. 도구 막대 아이콘은 성격별로 묶여 가로선으로 나뉘어요. 도구 막대 맨 아래의 접기 버튼(⌃)을 누르면 도구 아이콘(연필과 자) 버튼 하나만 남고, 다시 누르면 펴져요(열려 있던 패널도 함께 닫혀요). 모든 캔버스와 프로젝트 지도가 한 설정(`toolsShut`)을 같이 쓰고, 앱을 다시 켜도 기억해요. 오른쪽 위에는 아무것도 띄우지 않아요(범례는 2026-11-15에 빼고 관계 도구로 옮겼어요). 줌은 Ctrl+휠로 해요. 블록 위에서도 Ctrl+휠은 항상 줌이고, 그냥 휠은 블록 안을 스크롤하거나 캔버스를 움직여요.

## 동작

- **떠 있는 막대의 모양**: 세로 도구 막대는 폭 36(위아래 안쪽 3 + 아이콘 버튼 28×28, 아이콘 16), 반경 10, 그림자. 버튼에는 글이 없고 이름은 툴팁(`title`)과 접근성 이름(`aria-label`)이에요. 배경 없이 hover에만 면이 생기고, 묶음 사이에는 16×1 가로선(위아래 3). 주 버튼 하나만 강조색 면이에요. 열린 패널의 버튼(문서, 플레이북, 관계, `?`)은 선택 면이에요. 상태는 버튼 오른쪽 아래 6px 점으로 보여요: 관계는 펜이 기본 관계가 아닐 때 그 관계의 색, 플레이북은 하나를 골랐을 때 강조색.
- **도구 막대**(왼쪽 위, 세로). 버튼이 연 패널(블록, 문서, 플레이북, 관계)은 모두 같은 모양(제목 + × 머리, 줄 목록)으로 막대 오른쪽에 위가 맞춰 열리고, `?` 말풍선도 오른쪽으로 열려요. 패널은 한 번에 하나만 열려요.
  - **닫기**: ×, 같은 버튼 다시 누르기, 또는 캔버스 빈 곳 클릭으로 닫혀요(빈 곳 클릭은 ×와 같아요).
  - 프로젝트 지도: `[새 에이전트 +](주) [Lead 열기/만들기 Network] ─ [?]` → [캔버스 구성](two-level-canvas.md)
  - Lead 캔버스: `[워커 Bot](주) [프롬프트 MessageSquarePlus] [질문 MessageCircleQuestion] ─ [블록 SquarePlus] [관계 Spline · 펜 점] ─ [문서 FileText] [플레이북 BookOpen · 고름 점] ─ [?]`
  - 다른 에이전트의 캔버스(워커 캔버스): `[프롬프트] [질문] ─ [블록] [관계] ─ [문서] ─ [?]`. "워커" 버튼은 없어요. 워커 아래 워커는 사이드바 행 메뉴·에이전트 헤더 ⋯의 "워커 추가"로 만들어요. → [워커 계층](../orchestration/worker-hierarchy.md)
  - `블록`: 블록 패널에 "구조 블록", "영역"이 아이콘·이름·한 줄 설명으로 나와요. 고르면 패널이 닫히고 보이는 화면 가운데에 생기고 이름 창이 열려요. 빈 곳 우클릭으로 그 자리에 만들 수도 있어요. → [구조 그리기](structure-drawing.md)
  - `관계`: 프로젝트의 관계(선의 종류) 목록을 열어요. 줄을 누르면 그 관계가 펜이 되고(버튼 오른쪽 아래에 그 색의 점, 툴팁에 "펜: 이름"), 새로 긋는 선이 그 관계로 생겨요. → [관계](relations.md)
  - 플레이북 버튼은 고른 플레이북 이름을 140px까지 붙여 보여요.
  - 병합 방식 칩(`병합: 로컬/PR`)은 없어요. 병합 방식은 Lead 헤더의 병합 칩 → 설정 → 프로젝트에서 바꿔요.
- **줌 바**(`CanvasControls`, 왼쪽 아래)
  - −, + 버튼으로 줄이고 키워요.
  - 배율(%)을 누르면 100%로 돌아가요.
  - 전체 보기는 모든 블록이 보이게 맞춰요(최대 100%).
  - **선택한 것 보기**(전체 보기 옆, `Focus`): 고른 블록들이 화면에 꽉 차게 맞춰요(여백 10%, 캔버스의 최대 배율 200%까지 다가가요). 선을 골랐으면 그 선의 두 끝 블록을 봐요. 아무것도 고르지 않았으면 버튼이 꺼져 있어요. 프로젝트 지도에도 있어요.
  - 움직임은 설정의 모션 속도를 따라요.
- **선 모양**(설정 → 캔버스 → 선 → 연결선): 꺾은선(기본) / 직선 / 곡선. 꺾은선은 가로·세로로만 꺾여요(꺾이는 곳은 4px만 둥글게). 직선은 끝에서 끝까지 곧게 이어요. 에이전트 캔버스의 모든 선(계층, 참조, 프롬프트, 구조 화살표)과 프로젝트 지도의 선, 끄는 동안의 선이 모두 같은 모양이에요. 바꾸면 바로 모든 캔버스에 적용돼요.
- **연결점은 고정**이에요. 선은 처음 이을 때 두 블록이 마주 보는 쪽 연결점을 골라 붙고, 그 뒤에 블록을 옮겨도 같은 연결점에 그대로 붙어 있어요. 연결점은 캔버스 파일에 저장돼서 앱을 다시 켜도 그대로예요(Lead의 계층 선도). 되돌리기(Ctrl+Z)에는 들어가지 않아요: 연결점만 바꾼 것은 되돌릴 단계가 아니고, 블록이나 선을 되돌려도 남아 있는 선은 지금 연결점을 그대로 써요.
  - **연결점 바꾸기**: 선을 눌러 선택하면 양 끝에 작은 고리(강조색 테두리)가 보여요. 고리를 끌어 같은 블록의 다른 연결점에 놓으면 그쪽으로 옮겨 붙어요. 끝을 끌 수 있는 건 선택한 선뿐이라, 두 선이 한 연결점을 같이 써도 선택하지 않은 선은 움직이지 않아요. 다른 블록으로는 옮길 수 없어요(누가 누구를 이끄는지가 바뀌어서예요). 그때는 "다른 블록에 이으려면 선을 끊고 새로 이어요"가 떠요.
  - **연결점 규약** (선이 어느 쪽으로 붙는가)
    - **트리와 계층은 아래 → 위**: Lead에서 워커로 가는 계층 선, 그리고 에이전트가 `tree`로 그린 그림의 화살표는 부모의 아래쪽 연결점에서 나와 자식의 위쪽 연결점으로 들어가요. 자식이 옆으로 아주 멀리 있어도 같아요. 그래서 한 부모의 선이 모두 한 연결점에서 나와요. 거꾸로 올라가는 선(자식 → 부모)은 위에서 나와 아래로 들어가고, 같은 줄에 있는 둘을 잇는 선만 옆으로 붙어요.
    - **흐름은 옆으로**: `flow`로 그린 그림의 화살표는 오른쪽에서 나와 왼쪽으로 들어가요. 흐름이 아래 줄로 꺾여 되돌아오는 줄에서는 반대(왼쪽 → 오른쪽)이고, 꺾이는 곳(바로 아래 칸으로 가는 선)만 아래 → 위예요.
    - **그 밖의 선**(참조 선, 프롬프트 선, `grid`나 배치 없이 그린 화살표, 손으로 그은 화살표): 두 블록이 마주 보는 쪽이에요(위아래로 더 멀면 위아래, 옆으로 더 멀면 옆).
    - "같은 줄"은 위아래로 낮은 쪽 높이의 절반 넘게 겹칠 때예요.
    - 규약은 선이 **새로 생길 때**와 **연결점 자동 정리**, **트리로 다시 배치**, **배치 정리**를 할 때 적용돼요. 이미 붙어 있는 선은 저절로 옮겨지지 않아요(연결점은 고정). 손으로 옮긴 연결점도 그대로 있다가 자동 정리를 누르면 규약대로 돌아가요.
    - 화살표가 어느 배치의 것인지는 그릴 때 선에 적어 둬요(`flow`). 그 전에 그려진 화살표는 두 끝이 든 영역이 `tree`·`flow`로 그려졌는지를 봐요(영역에 `layout`이 적혀 있을 때).
  - **연결점 자동 정리**: 줌 바 끝의 `Waypoints` 버튼을 누르면 지금 블록 자리에 맞게 모든 선의 연결점을 한 번 다시 골라요(위 규약대로: 트리와 계층은 아래 → 위, 흐름은 옆으로, 나머지는 마주 보는 쪽). 프롬프트 블록은 연결점이 하나라 그쪽 끝은 그대로예요. Lead 캔버스가 카드를 트리로 다시 놓을 때도 같은 정리를 해요. 프로젝트 지도에는 이 버튼이 없어요(선이 늘 아래 → 위).
- **선**(연결선): 모든 선은 **관계**의 하나이고 모양을 관계에서 받아요(→ [관계](relations.md)). 패턴은 실선 · 긴 점선(6 4) · 짧은 점선(둥근 점), 머리는 → · ↔ · 없음, 색은 기본 선 색(`--mae-edge`, 캔버스 색에 글자색 28%를 섞은 불투명한 색, 밝은 테마 32%) 또는 관계의 옅은 색 6가지(`--mae-rel-*`, 역시 불투명)예요. 투명도가 없어서 두 선이 한 연결점에서 겹쳐도 겹친 곳이 진해지지 않아요. 확대 배율과 상관없이 화면에서 1px이에요(짧은 점선만 점이 보이게 1.5px).
  - 내장 관계: Lead → 워커(지휘), 프롬프트 → 에이전트(지시), 그냥 그은 구조 선(기본 관계)은 실선, 문서 참조(참조)는 긴 점선이에요.
  - 일하는 중은 모양이 아니라 상태예요: 계층 선은 그 워커가 일하는 동안 작은 점(실행 중 색)이 선을 따라 흘러가요(1.6초). 선의 패턴은 그대로예요. 모션을 끄거나 운영체제의 동작 줄이기를 켜면 점이 나오지 않아요.
  - 화살촉은 작게 고정돼 있고(선을 굵게 해도 커지지 않아요) 선과 같은 색이에요.
  - 마우스를 올리면 한 단계 밝은 색(두 번째 글자색) 1.5px, 선택하면 강조색 1.5px이 돼요.
  - 선 정보는 네 단계로 봐요: 평소 라벨(설정의 "선 라벨"이 항상일 때), 호버 카드, 선택하면 제목 블록(관계 바꾸기 · 편집 · 블록으로 꺼내기 · ×), 더블클릭하면 편집 창. → [관계](relations.md)
  - 프로젝트 지도의 선은 읽기 전용이라 마우스를 올려도 바뀌지 않아요.
  - 선을 끄는 동안에는 끄는 선이 점선(두 번째 글자색)이고, 모든 블록의 연결점이 흐리게 보이며 놓을 수 있는 연결점은 강조색으로 밝아져요. 연결점은 보이는 점보다 6px 넓게 잡혀요.
- **선택:** 에이전트 캔버스의 빈 곳을 왼쪽 버튼으로 끌면 선택 상자가 생기고, 상자에 조금이라도 걸린 블록이 모두 선택돼요. 선은 상자로 잡히지 않고 클릭해야 선택돼요. Shift(또는 Ctrl) 클릭으로 블록을 선택에 더하거나 빼요. 선택된 블록은 강조색 테두리가 생기고, 함께 끌어 옮기거나 Delete로 지울 수 있어요(에이전트 블록과 워커 카드는 지워지지 않아요).
- **화면 이동:** 휠 버튼(가운데 버튼)을 누른 채 끌거나, Ctrl을 누른 채 왼쪽 버튼으로 끌어요(Ctrl을 누르면 빈 곳 커서가 손 모양이 돼요). 그냥 휠은 지금처럼 화면을 움직여요. 프로젝트 캔버스는 선택이 없어서 왼쪽 버튼 끌기로도 움직여요.
- **Ctrl+휠:** 어디서든 줌이에요. 트랙패드 핀치도 Ctrl+휠로 들어와서 똑같이 동작해요.
- **Ctrl+Z / Ctrl+Shift+Z(Ctrl+Y):** 에이전트 캔버스에서 블록 이동·크기·추가·삭제, 선 연결·끊기를 되돌리고 다시 해요. 마지막으로 누른 캔버스에만 먹고, 입력창·에디터·터미널 안에서는 그쪽 실행 취소가 돼요. 워커 연결과 참조처럼 백엔드에 저장된 연결은 되돌리지 않아요.
- **Delete**(macOS는 Backspace도): 선택한 블록과 선을 지워요. 마지막으로 누른 곳이 이 캔버스이고 캔버스가 화면에 보일 때만이에요. 사이드바·파일 트리·코드 탭에 포커스가 있거나, 다른 분할 화면을 눌렀거나, 입력칸·편집기·터미널·대화상자 안이면 캔버스는 지우지 않아요.
- **방향키**는 블록을 움직이지 않아요(React Flow 키보드 이동 끔). 대화 안에서는 스크롤, 사이드바에서는 행 이동이에요.
- **선을 빈 곳에 놓아 워커 만들기**: 끈 선을 캔버스 빈 곳(블록, 도구 막대, 미니맵, 입력창 위가 아닌 곳)에 놓았고, 연결점에서 한 칸(24px) 이상 끌었을 때만 새 워커 창이 열려요.
- **더블클릭**: 블록 안의 버튼, 입력칸, 링크를 더블클릭하면 그 버튼만 동작해요(전체 화면 전환이나 워커로 들어가기는 블록 자체를 더블클릭할 때만). 블록이 연 대화상자(변경 보기 등) 안의 클릭과 더블클릭도 블록으로 넘어가지 않아요.
- **문서 끌어 놓기**: Markdown 파일을 입력창(블록, 아래 입력창)이나 프롬프트 블록에 놓으면 거기에만 첨부돼요. 캔버스에 Markdown 블록이 따로 생기지 않아요.
- **캔버스 파일이 깨졌을 때**: 읽을 수 없는 캔버스 파일(정상 `.bak`도 없음)은 빈 캔버스로 열고 알림을 띄워요. 다음 저장이 깨진 파일을 옆으로 옮겨요. 더 새 Maestro가 쓴 파일은 예전처럼 열지도 덮어쓰지도 않아요.
- **배치는 저절로 바뀌지 않아요**: 트리 배치는 한 번도 트리로 놓인 적 없는 Lead 캔버스를 처음 열 때만 해요. 그 뒤로 누가 누구를 이끄는지 바뀌어도(백그라운드에서 Lead가 워커를 만들어도) 이미 놓인 카드는 움직이지 않고, 새 카드만 자기 Lead 아래 첫 빈자리에 놓여요. 다시 트리로 놓고 싶으면 빈 곳 우클릭 → "트리로 다시 배치"(Lead 캔버스만). 이 캔버스의 입력칸에 쓰는 중이면 새 카드나 에이전트가 그린 구조로 화면을 옮기지 않아요.
- **프롬프트 블록 추가**: 이 캔버스 화면 가운데(분할이면 그 칸 가운데)에 생기고, 이미 있는 프롬프트 블록 수만큼 한 칸씩 비켜 놓여요. 새 블록이 선택되고 입력칸에 바로 커서가 가요. 이름은 쓰고 있는 가장 큰 번호 + 1이라 겹치지 않아요.
- **연결 규칙**: 프롬프트 블록과 에이전트(에이전트 블록, Lead 캔버스의 워커 카드)는 어느 쪽에서 끌어도 이어져요(저장은 늘 프롬프트 → 에이전트). 워커 → 그 워커를 이끄는 쪽(멀리 위쪽이라도)처럼 고리가 생기는 연결은 끄는 동안부터 받지 않아요. 이미 다른 Lead 아래 있는 워커를 이으면 "워커 옮기기 · <이름>" 확인 창에서 옮길지 물어요.
- **끊기와 되돌리기**: Lead → 워커 선을 끊으면 "워커 연결 끊기" 확인 창을 거쳐요(되돌리기로 다시 잇지 않아서예요). Markdown 블록이나 참조 선을 지워 빠진 참조는 Ctrl+Z로 그 블록이나 선이 돌아올 때 다시 이어져요.
- **보내기**: 모든 입력칸(에이전트 블록, 아래 입력창, 워커 카드의 바로 지시하기, 프롬프트 블록)이 Enter로 보내고 Shift+Enter로 줄을 바꿔요. 보내는 동안에는 "보내는 중…"이고 다시 보내지지 않아요. 워커 카드 입력칸은 보낸 뒤에도 커서가 남아요.
- **아래 입력창**: 대화를 끌어 올려도 캔버스 높이를 넘지 않아요. 이 캔버스의 에이전트 블록이 펼쳐져 있으면 승인·병합 카드는 블록에만 보여요(두 벌로 나오지 않아요). 입력창이 열린 채 캔버스가 좁으면 미니맵(1100px 이하)과 줌 바(700px 이하)가 비켜요.
- **축소해서 볼 때**: 60% 미만으로 줄여 대화가 마지막 글만 남아도 승인·병합 카드는 블록에 그대로 보여요.
- **미니맵**: 영역 안 블록도 제자리에 그려요. 영역은 점선 테두리, 문서·구조 블록은 옅은 면, 에이전트는 진한 면이에요. 접힌 영역이 숨긴 블록은 그리지 않아요.
- **메뉴**: 워커 카드는 머리의 ⋯나 우클릭, 지도 카드는 우클릭으로 사이드바 행과 같은 에이전트 메뉴가 열려요. 에이전트 블록은 머리의 ⋯예요.
- **우클릭 메뉴**(에이전트 캔버스, 앱 공통 메뉴 `Menu`로 포인터 자리에 떠요). 열면 도구 막대의 열린 패널은 닫혀요.
  - 빈 곳: 구조 블록 추가 · 영역 추가 · 프롬프트 블록 추가 · 질문 블록 추가 · 새 워커…(Lead 캔버스만) · ─ · 전체 보기 · 연결점 자동 정리 · 트리로 다시 배치(Lead 캔버스만). 추가한 블록은 우클릭한 자리가 가운데가 되게 놓여요.
  - 구조 블록: 이름·메모 편집… · 선으로 합치기(합칠 수 있을 때) · 테두리 색… · ─ · 지우기. 영역: 영역 편집…(이름, 색, 단계·상태, 든 것) · 여기에 구조 블록 추가(그 영역 안에) · 내용에 맞추기 · 작게 접기 · 테두리 색… · ─ · 지우기. 접힌 영역: 영역 편집… · 펼치기 · 테두리 색… · ─ · 지우기(→ [영역](zones.md)). 단계·상태가 있는 영역 안의 블록(구조 블록, 문서, 질문, 영역)에는 "보이는 단계…"(상태 영역이면 "보이는 상태…")가 더 나오고, 두 끝이 그런 영역 안에 있는 그린 선에도 나와요. "테두리 색…"을 고르면 같은 자리에 색 메뉴(색 없음 + 여섯 색)가 열려요. 여러 개를 선택했으면 그 가운데 구조 블록과 영역에 한 번에 줘요. 문서(Markdown) 블록: 캔버스에서 빼기(파일은 그대로). 프롬프트 블록: 지우기. 질문 블록: 질문 편집…(답하기 전이면 에이전트의 질문도) · ─ · 지우기.
  - 선: 선 편집… · 블록으로 꺼내기(구조 선만) · ─ · 선 지우기(Lead → 워커 선은 "워커 연결 끊기…", 확인 창을 거쳐요).
  - 선택하지 않은 것을 우클릭하면 그것만 선택돼요(클릭처럼). 선택된 것을 우클릭하면 선택이 그대로이고, 여럿이면 편집 항목 없이 "선택한 N개 지우기"만 나와요. 지우기는 Delete와 같은 길이에요(영역을 지워도 안의 블록은 남아요).
  - 워커 카드와 에이전트 블록은 자기 메뉴(에이전트 메뉴, 머리의 ⋯)를 써요. 블록 안의 입력칸·터미널·편집기에서는 시스템 메뉴(복사, 붙여넣기)가 그대로 떠요.
- **구조 블록 편집 창**: 메모를 읽는 보기 모드에서도 창이 포커스를 받아 Esc로 닫히고, Delete나 방향키가 뒤의 캔버스로 가지 않아요.
- **?(사용법, `CircleHelp`):** 그 캔버스에서 할 수 있는 일을 한 줄씩 보여 줘요. 누르면 열리고, 말풍선을 누르거나 다시 누르면 닫혀요. 모든 캔버스의 마지막 두 줄은 메뉴로 옮긴 조작 안내예요: "우클릭과 ⋯로 메뉴를 열어요", "프로젝트 분할은 프로젝트 메뉴 → 분할로 열기".
- **화면이 따라가기** (에이전트가 캔버스를 바꿨을 때 화면이 어디를 보는가)
  - 전에는 무엇을 그리든 캔버스 전체가 보이게 맞췄어요. 이제 **바뀐 곳**을 봐요.
  - **① 새로 생긴 것을 먼저 봐요.** 새 그림, 질문 블록, 질문 묶음, 보기 블록이 생기면 그것이 화면 가운데에 오게 옮기고 맞춰요(최대 100%: 작은 블록 하나를 크게 부풀리지 않아요).
  - **② 이어진 구조가 있으면 잠시 뒤 그 전체를 봐요.** 새것이 든 영역(가장 바깥 영역까지)과, 그 영역에 화살표로 이어진 것들을 끝까지 따라간 전체예요. ①에서 약 1.2초 머문 뒤 넓혀요. 새것이 혼자면(따로 그린 새 그림, 혼자 놓인 질문) ②는 없어요. 관계없는 다른 그림까지 보여 주려고 캔버스 전체로 넓히지 않아요.
  - 새로 생긴 것이 없고 있던 것이 바뀌기만 했으면(블록의 메모, 새 화살표의 두 끝, 에이전트가 넘긴 단계·상태) 그 바뀐 것을 ①처럼 보고 ②로 넓혀요.
  - **이미 보이면 움직이지 않아요.** 볼 곳이 화면 안에 다 들어와 있고 크기도 옮겼을 때와 비슷하면(그 배율의 3/4 이상) 그대로 둬요. 화면이 멀리 줄어 있어서 새것이 작게만 보이면 다가가요.
  - **사용자가 하던 일을 뺏지 않아요.** 이 캔버스에서 글을 쓰는 중이거나 블록을 끌거나 크기를 조절하는 중이면 움직이지 않아요. ①과 ② 사이에 사용자가 화면을 직접 움직이거나 블록을 집으면 ②는 하지 않아요.
  - 지워진 것만 있으면 움직이지 않아요. 접힌 영역 안이나 지금 단계에 없어 보이지 않는 것은, 그것을 대신 보여 주는 가장 가까운 것(접힌 칩, 그 영역)을 봐요.
  - 캔버스가 닫힌 동안 그려진 것은 열 때 한꺼번에 놓이고, 그때 같은 규칙으로 봐요.
  - 사용자가 손으로 한 일(블록 추가, 끌기)에는 화면이 따라가지 않아요. 새 워커 카드가 생길 때 그 카드로 가는 것은 따로 있는 동작이에요.
  - **새것 강조**: 에이전트가 방금 놓은 것(새로 생긴 것이 없으면 바뀐 것)의 둘레에 강조색 테두리가 3초쯤 켜졌다가 사라져요. 화면이 넓혀진 뒤에도 어느 것이 새것인지 보여요. 새 영역은 영역 하나에만 켜요(그 안의 블록마다 켜지 않아요). 접힌 영역 안에 그려졌으면 그 칩에 켜요.
  - **질문 먼저**: 한 번에 온 것 가운데 답을 기다리는 질문이 있으면 화면이 질문으로 먼저 가고, 나머지는 넓혀질 때 함께 보여요. 에이전트가 그 답에서 멈춰 있기 때문이에요.
  - **답을 기다리는 질문 알림**: 에이전트가 물은 질문이 답 없이 화면 밖에 있으면, 위쪽에 "답을 기다리는 질문" 알림이 경고색 테두리로 계속 떠 있어요(화살표가 방향을 가리키고, 누르면 그리로 가요). 답하거나 질문이 화면에 들어오면 사라져요. 닫기 버튼은 없어요.
  - **보던 곳으로**: 화면이 저절로 옮겨지면 왼쪽 아래 줌 바에 "보던 곳으로" 버튼(`RotateCcw`)이 생겨요. 누르면 옮겨지기 전에 보던 자리와 배율로 돌아가고 버튼은 사라져요. 화면이 여러 번 이어서 옮겨져도(설명을 따라 넘어갈 때) 돌아갈 곳은 처음 보던 자리예요. 사용자가 직접 화면을 움직인 뒤 다시 저절로 옮겨지면 그때의 자리로 바뀌어요.
  - **끄기**: 설정 → 캔버스 → "화면 따라가기"를 끄면 화면은 움직이지 않고, 새로 생긴 것은 강조와 화면 밖 알림으로만 알려요.
  - **에이전트가 볼 곳을 짚기**: `maestro focus --title 이름`이 화면을 그 블록·영역·질문·보기 블록으로 옮기고 테두리를 밝혀요(구조 전체로 넓히지는 않아요).
  - **화면 밖 알림**: 글을 쓰는 중이거나 블록을 잡고 있어서 화면이 움직이지 못했고, 생긴 것이 화면 밖(절반 넘게 안 보임)이면 캔버스 위쪽 가운데에 알림이 떠요. "새로 생긴 것 2개", "바뀐 것 1개", 질문만이면 "새 질문"이라고 적히고, 화살표가 그것이 있는 방향을 가리켜요. 누르면 화면이 그리로 가고 테두리가 다시 켜져요. ×로 닫아요. 사용자가 직접 화면을 옮겨 그것을 보게 되면(절반 넘게 보이면) 알림은 저절로 사라져요. 여러 번에 걸쳐 생긴 것은 하나의 알림에 모여요. 알림은 저장하지 않아요(캔버스를 다시 열면 없어요).
- **안내와 그림 넘기기** (에이전트가 놓는 것이 한 걸음씩, 설명 한 줄과 함께 들어와요. 게임에서 대사를 넘기는 것처럼)
  - **안내 한 줄**: 에이전트는 캔버스에 놓는 것마다 한 줄을 붙일 수 있어요(`--say`, 그림 파일의 `"say"`, 그림 없이 `maestro say --text`). 그 줄이 캔버스 위쪽 가운데에, 캔버스의 다른 무엇보다 위에 떠요. 떴다가 설정한 시간 뒤에 흐려지며 사라져요.
  - **한 걸음**: 한 줄이 한 걸음이에요. 한 줄과 그 뒤에 줄 없이 온 것들이 함께 한 걸음으로 들어와요. 그 걸음의 것이 나타나고, 화면이 그리로 가고(위 "화면이 따라가기"), 줄이 떠요.
  - **자동**(기본): 걸음이 차례로 저절로 들어와요. 줄이 있는 걸음은 그 줄의 시간만큼 머물렀다가 다음으로 넘어가요. 줄이 없는 것은 전처럼 오는 즉시 나타나요. 안내를 누르면 기다리지 않고 바로 다음으로 넘어가요.
  - **눌러서**: 에이전트가 놓은 것이 바로 나타나지 않고 기다려요. 캔버스 위쪽에 "에이전트가 보여 줄 것이 N개 있어요 · 보기"가 뜨고, 누를 때마다 한 걸음씩 나타나요. 다음 걸음이 기다리면 안내에 "다음 ›"과 남은 수가 보여요. 마지막 걸음의 줄은 시간 뒤에 사라져요.
  - **채팅의 허용**: 눌러서일 때, 기다리는 것이 있으면 그 에이전트의 채팅(아래 입력창, 에이전트 블록, 전체 화면 채팅)의 승인 카드 자리에 "캔버스 · 보여 줄 것이 N개 기다려요 · 허용" 카드가 떠요. 허용을 누르는 것은 캔버스의 안내를 누르는 것과 같아요(한 걸음). 캔버스가 열려 있지 않을 때(전체 화면 채팅) 누른 허용은 기억해 뒀다가 캔버스를 열 때 그만큼 나타나요.
  - **설정**(설정 → 캔버스 → 에이전트의 시각화): "시각화 허용" 자동 / 눌러서, "안내 시간" 2 · 4 · 6 · 10초(기본 4초), "화면 따라가기".
  - 기다리는 것은 화면에만 안 보일 뿐 캔버스에는 이미 놓여 있어요(저장도 돼요). 그래서 에이전트가 이어서 하는 일(그 영역의 단계 넘기기, 이름으로 지우기, 그 위에 더 그리기)이 어긋나지 않아요. 걸음이 "하는 일"(영역의 단계·상태 넘기기, 화면 짚기, 배치 정리)은 그 걸음 차례에 일어나요. 지우기는 기다리지 않고 바로 지워져요.
  - 캔버스를 닫았다 열면 기다리던 것은 모두 보이는 채로 와요(기다림은 저장하지 않아요).

- 선(Canvas.tsx `LinkEdge`, `ARROW`, `EDGE_COLOR`, styles.css "connection lines"): `vector-effect: non-scaling-stroke`로 화면 1px. 화살촉은 `markerUnits: "userSpaceOnUse"`(16×16 상자 안 작은 머리), 색은 `<ReactFlow defaultMarkerColor="var(--mae-edge)">`. 계층 선은 데이터에 워커 경로(`child`)를 들고 있다가, 그 워커의 상태가 RUNNING이고 모션이 켜져 있으면 `.flowing` 클래스(점선 4 4, `edge-flow`)를 붙여요. React Flow의 `animated`는 쓰지 않아요. 프롬프트 선도 `type: "link"`, `className: "pipe"`라 테마 색과 끊기 ×를 받아요. 끄는 동안 `onConnectStart`/`onConnectEnd`가 캔버스에 `.connecting`을 붙여요.

## 제약과 알려진 문제

- 연결점 규약과 선택한 것 보기는 화면에서 확인하지 않았어요(2026-11-18, 타입 검사와 규칙 시험만).
- 규약이 들어가기 전에 그린 트리 그림은 선에도 영역에도 배치가 적혀 있지 않아서, 연결점 자동 정리를 눌러도 마주 보는 쪽으로 붙어요(다시 그리면 규약대로 붙어요). 계층 선(Lead → 워커)은 예전 캔버스에서도 자동 정리 한 번이면 아래 → 위가 돼요.
- 화면이 따라가기는 화면에서 확인하지 않았어요(2026-11-18, 타입 검사와 규칙 시험만). 머무는 시간(1.2초)과 "이미 보인다"의 기준(3/4)은 써 보고 정한 값이 아니에요.
- 안내와 그림 넘기기, 채팅의 허용, 질문 먼저, 보던 곳으로, `maestro focus`·`say`는 화면에서 확인하지 않았어요(2026-11-18, 타입 검사와 시험만).
- 눌러서일 때 기다리는 것은 보이지 않지만 캔버스에 있어요: 그 자리를 차지하고, 전체 보기와 미니맵에 들어가고, 든 영역이 그만큼 커져 있어요. 지우기는 차례를 기다리지 않아요.
- 에이전트의 일은 허용을 기다리지 않아요. 넘기기는 "보이는 때"를 정할 뿐이고, 에이전트는 그리는 명령을 내린 뒤 바로 다음 일을 해요.
