# 캔버스 구성

## 요약

캔버스는 세 가지예요.
- **프로젝트 캔버스(`ProjectMap`):** 사이드바에서 프로젝트를 누르면 나와요. 구조만 보여 주고, 항상 트리 모양이에요.
- **Lead 캔버스:** Lead 에이전트 블록 아래에 워크트리 카드들을 놓고 연결선과 참조를 편집해요.
- **워크트리 캔버스:** 워크트리 하나의 에이전트 블록과 프롬프트 블록을 놓아요.

처음 여는 화면은 역할마다 달라요. Lead는 캔버스(워커들이 보이는 곳)로, 다른 에이전트는 전체 화면으로 열려요(설정 → 일반 → 열 때 화면, `maestroLayout`·`agentLayout`). 탭 줄 오른쪽 버튼으로 그 탭만 바꿔요.

## 동작

**프로젝트 캔버스**
- 카드(`structure_card`, 336×168 = 격자 14×7, 머리 28)마다 상태 글리프, 이름, 외부 배지, 에이전트 로고, 설명, 참조 문서·페르소나 칩, 브랜치와 워커 수가 보여요.
- Lead 카드의 아래 줄 끝에는 워커마다 6px 점(`WorkerDots`)이 상태 색으로 보여요(승인 대기 경고색, 작업 중, 새 응답, 쉬는 중, 꺼짐·에이전트 없음은 빈 원). 최대 8개, 넘치면 "+N". 점에 마우스를 올리면 "<워커 이름> · <상태>"예요. 지도에서는 워커 행이 안 보여서 Lead 카드에만 둬요.
- 카드를 더블클릭하면 그 에이전트로 들어가요.
- "+" 칩을 누르면 참조 문서 선택 창(`RefPicker`)이 열려요.
- 위쪽 도구 막대: `[새 에이전트](주) [Lead 열기 | Lead 만들기] │ [?]`. "Lead 열기"는 Lead를 고정 탭으로 열어요(역할별 첫 화면, 기본 캔버스). → [캔버스 조작](canvas-controls.md)
- 에이전트가 하나도 없으면 가운데 빈 상태(폭 360): "아직 에이전트가 없어요" + "에이전트마다 따로 된 작업 폴더(워크트리)와 브랜치에서 일해요" + [새 에이전트](주) [Lead 만들기].
- 여기서는 연결을 바꾸지 않아요.

**Lead 캔버스**(`Canvas`, `scope` = Lead)
- 맨 위에 Lead 에이전트 블록이 있고, 아래에 워크트리 카드(`worktree_card`)가 놓여요.
- 워커 카드(336×264 = 격자 14×11, 머리 28)에 보이는 것:
  - 상태와 변경된 파일 수
  - 최근 답변 요약 → [답변 요약](../agents/answer-summaries.md)
  - 바로 지시를 보내는 작은 입력창(Enter 또는 [보내기])
  - **확인 줄**: 이 워커에게 확인할 일이 있으면 입력창 자리를 같은 높이(48px)의 한 줄이 잠시 차지해요. 도구 승인 = "Bash · npm test" + [허용] [거부] [열기], 터미널 질문 = "터미널 질문" + [터미널에서 답하기] [열기], 이 워커 브랜치의 병합 요청 = "병합 요청 · 파일 N" + [변경 보기] [열기]. 한 번에 한 건이고(승인 → 터미널 질문 → 병합 요청 순), 답하면 다음 건이나 입력창이 돌아와요(쓰던 지시는 남아요). [열기]는 그 워커를 고정 탭으로 열어요. 카드 테두리는 경고색이에요. 예전 `병합 요청` 칩은 없어요. → [확인할 일](../ui/attention.md)
- 연결:
  - 계층선(Lead → 워커)과 참조선(마크다운 → 에이전트)을 이 캔버스에서 만들고 끊어요.
  - 선을 고르면 ×가 나와요. ×를 누르거나 Delete 키로 끊어요.
  - 카드에서 선을 끌어 빈 곳에 놓으면 그 카드의 워커로 새 워크트리를 만들어요. → [워커 계층](../orchestration/worker-hierarchy.md)
- 도구 막대: `[워커](주) [프롬프트] │ [블록 ▾] │ [문서] [플레이북] │ [?]`. 워커 캔버스(다른 에이전트의 캔버스)는 `[프롬프트] │ [블록 ▾] │ [문서] │ [?]`이고 "워커"가 없어요. → [캔버스 조작](canvas-controls.md)
- 카드를 더블클릭하면 그 워크트리로 들어가요.

**에이전트 화면(역할별 첫 화면)**
- 새 탭이 처음 여는 화면: Lead면 설정 `maestroLayout`(기본 캔버스), 다른 에이전트면 `agentLayout`(기본 전체 화면). 사이드바 행, 프로젝트 지도의 "Lead 열기", 확인할 일, Ctrl+Shift+↑/↓ 등 어디서 열어도 같아요. 이미 열린 탭은 자기 보기를 그대로 써요.
- 전체 화면(`AgentFull`)은 Claude Code 앱처럼 에이전트 하나가 탭을 채워요.
- "전체 화면 / 캔버스" 전환은 탭 줄 오른쪽 묶음의 버튼 하나예요(전체 화면에서는 `Workflow` "캔버스로 보기", 캔버스에서는 `Maximize2` "전체 화면으로 보기"). 두 보기에서 같은 자리이고, 그 탭만 바꿔요(탭의 `layout`, `setTabLayout`). 설정은 바꾸지 않아요. → [가운데 화면 탭](../ui/stage-tabs.md)
- 아래 입력창의 전체 화면 버튼, 블록 헤더 더블클릭도 그 탭만 전체 화면으로 바꿔요.
- 캔버스에서는 에이전트 블록(`pty_terminal_node`)과 프롬프트 블록을 자유롭게 놓아요. 블록 오른쪽 아래 모서리를 끌어 크기를 바꿔요.
- 에이전트 블록의 채팅/터미널은 블록마다 저장하지 않아요. 전체 화면·분리 창과 같이 설정의 에이전트 보기를 따르고, 블록 헤더의 보기 아이콘은 그 에이전트만 잠시 바꿔요(같은 에이전트를 전체 화면으로 열어도 같은 보기예요). 앱을 다시 켜면 다시 에이전트 보기로 떠요. → [채팅 뷰](../agents/chat-view.md)
- 뒤로 버튼으로 프로젝트로 돌아가요.

**공통**
- 블록 위치는 격자(`GRID`)에 맞춰져요.
- 캔버스마다 배치와 화면 위치가 저장돼요.
- 처음 열거나 트리 배치 전에 저장된 캔버스는 한 번 트리로 자동 배치돼요(`treeLayout`).
  - Lead가 맨 위, 워커는 부모 아래, 형제는 옆으로 놓여요.
  - 상위가 없는 워크트리도 Lead 아래에 선 없이 놓여요.
- 연결점은 블록 네 변에 있어요. 선은 두 블록이 마주 보는 변에서 나가고 들어와요(`facingSides`).
- **에이전트 블록 접기**: 에이전트 블록 헤더의 접기 버튼을 누르면 작은 블록(336×96 = 격자 14×4)이 돼요. 블록 가운데를 기준으로 줄어들고 펼칠 때도 가운데에서 커지며(격자에 맞추면 가운데에서 벗어나서 이때만 맞추지 않아요), 설정의 모션 속도를 따라 움직여요. 상태 글리프, 에이전트 로고, 이름, 그 아래 페르소나·참조 문서 태그(최대 두 줄)만 보이고, 승인을 기다리면 "승인 대기"가 붙어요. 작업 중은 글리프의 도는 고리로 보여요(따로 된 로딩 표시는 없어요). 이 블록을 누르면 아래 입력창이 열리고, 다시 누르면 닫혀요. 알약의 펼치기 버튼을 누르면 접기 전 크기의 창으로 돌아가요. 접은 상태는 캔버스와 함께 저장돼요.

- **아래 입력창**: 에이전트 캔버스 맨 아래 가운데에 높이 32 알약 버튼이 있어요. 그 에이전트의 로고 16 + "<이름>에게 지시"(Lead 캔버스면 "Lead에게 지시", 최대 240px 말줄임). 누르면 그 위에 이 캔버스 에이전트에게 보내는 입력창(승인 카드 포함)이 열리고, 버튼은 둥근 Lead 로고 "입력창 닫기"로 바뀌어요(마우스를 올리면 로고가 로딩 모양으로 움직여요). 입력창 위쪽에는 상태 글리프, 에이전트 이름, LLM 로고와 이름, 닫기(`X`)가 있어요. 입력창 폭은 왼쪽 줌 바와 오른쪽 미니맵을 피하도록 캔버스 폭에 맞춰 줄어요(최대 680px). 캔버스의 다른 곳을 눌러도 닫히지 않고, 같은 버튼(또는 접힌 에이전트 블록)을 다시 눌러야 닫혀요.
- **아래 입력창에서 대화 보기**: 입력창 맨 위 손잡이를 끌어 올리면 그만큼 대화 내용이 입력창 위에 보여요(최대 화면 높이의 60%). 끌어 내리면 줄고, 조금만 남기면 닫혀요. 헤더의 화살표 버튼(또는 손잡이 더블클릭)은 가장 작은 높이(160px)로 열고 닫아요. 높이는 에이전트마다 기억해요.
- **전체 화면으로**: 아래 입력창 헤더의 전체 화면 버튼, 또는 캔버스 에이전트 블록의 헤더(접힌 블록이면 블록)를 더블클릭하면 그 에이전트 전체 화면으로 넘어가요. 채팅 안을 더블클릭하는 건 글자 선택이라 넘어가지 않아요. 캔버스로 돌아오면 아래 입력창이 열려 있던 그대로예요(앱을 켜 둔 동안 캔버스마다 기억).
- **선택을 함께 보내기**: 캔버스에서 블록(워커, 문서, 프롬프트 블록)을 선택한 채 아래 입력창을 쓰면, 입력창 위에 "선택 N개" 칩과 이름들이 보여요. 이대로 보내면 메시지 앞에 `[캔버스에서 선택한 블록]` 목록이 붙어요(슬래시 명령과 `!` 명령에는 안 붙어요). 칩의 ×를 누르면 캔버스의 선택도 함께 풀려요(그래서 `maestro selection`도 비어요). 에이전트는 `maestro selection`으로도 지금 선택을 읽을 수 있어요. → [maestro CLI](../orchestration/maestro-cli.md)
- **워커 카드 접기**: Lead 캔버스의 워커 카드도 헤더의 접기 버튼으로 간소화할 수 있어요. 헤더(이름, 에이전트), 연결된 페르소나(`♟`)와 참조 문서(`≡`) 태그(최대 두 줄, 나머지는 잘리고 마우스를 올리면 전부 보여요), 아래 바로 지시 입력창만 남고 설명, 페르소나, 변경 수, 답변 요약은 숨겨요(폭 312, 높이는 내용만큼: 태그가 없으면 헤더 한 줄, 있으면 이름 아래 태그 줄만큼 길어져요. 카드가 자기 높이를 재서 블록 크기를 맞춰요). 승인을 기다리면 입력창 자리에 확인 줄이 보여요(헤더의 "승인 대기" 글자는 없앴어요, 글리프가 보여 줘요). 같은 버튼(`Maximize2`/`Minimize2`)으로 다시 펼쳐요.

**블록 크기**(모두 24px 격자 칸의 배수라 블록 가장자리가 격자선에 맞아요)
| 블록 | 크기(격자 칸) | px |
|---|---|---|
| 문서(Markdown) 블록, 구조 블록 | 10 × 3 | 240 × 72 |
| 프롬프트 블록 | 너비 14(높이는 내용) | 336 |
| 접은 에이전트 블록, 접은 워커 카드 | 14 × 4 | 336 × 96 |
| 워커 카드 | 14 × 11 | 336 × 264 |
| 지도 카드 | 14 × 7 | 336 × 168 |
| 영역 | 18 × 12(처음 크기) | 432 × 288 |
| 에이전트 블록 S / M / L | 20 × 15 / 28 × 21 / 36 × 27 (모두 4:3) | 480 × 360 / 672 × 504 / 864 × 648 |

- 너비는 세 단계예요: 작은 블록 10칸, 카드·접은 블록 14칸, 에이전트 블록 20·28·36칸. 접으면 모두 높이 4칸이에요.
- 크기를 끌어 바꾸면 격자 칸 단위로만 바뀌어요(에이전트 블록 18×14 ~ 50×40칸, 구조 블록 최소 4×2칸, 영역 최소 8×5칸). 예전에 칸에서 어긋나게 저장된 크기는 열 때 가장 가까운 칸으로 맞춰요.
- 이미 놓인 에이전트 블록은 저장된 크기를 그대로 써요. 새 프리셋(4:3)은 새로 만드는 블록부터예요.

## 구현

- 화면 고르기(`GroupView`, Workspace.tsx):
  - 선택 없음 → `ProjectMap`
  - 에이전트(Lead 포함) → `useTabLayout(group)`(store.ts)이 `full`이면 `AgentFull`, 아니면 `Canvas`. 탭의 `layout`이 없으면 `roleLayout(isMaestro)`.
- 새 탭의 보기: `select(path, pin)`이 그 경로의 `Worktree.isMaestro`로 `roleLayout`을 골라 탭의 `layout`에 적어요. 이미 있는 탭은 `withTab`이 자기 `layout`을 지켜요.
- 저장: `load_canvas_state` / `save_canvas_state(project_root, key)`
  - 저장 위치는 `~/.maestro/projects/<프로젝트>/canvases/<key>.json`이에요. → [저장 위치](../../reference/storage-layout.md)
  - 형식은 `CanvasStateSchema`(types.ts)예요. `tree: 1`이면 트리 배치를 한 번 했다는 뜻이에요.
- 노드 종류: `nodeTypes = { prompt_input_primitive, pty_terminal_node, worktree_card, markdown_block }`
- 선 종류: `CanvasEdge.data.kind`
  - `command_pipe`(프롬프트 → 에이전트, 캔버스에 저장)
  - `orchestrates`(계층), `reference`(참조) — 이 둘은 에이전트 메타에서 그려요
- 연결 모드는 `ConnectionMode.Loose`예요. 네 변의 연결점이 모두 `source` 타입이어도 서로 이어져요.
- 줌을 많이 줄이면(`LOD_ZOOM` 아래) 블록이 가벼운 모양으로 그려져요.
- 접기: 노드 데이터의 `compact`(접힘)와 `full`(펼칠 때 크기). `AgentChip`이 알약, `AgentBar`가 아래 입력창이에요(AgentNode.tsx). 캔버스의 `barOpen` 상태가 아래 입력창을 열고 닫아요(모듈의 `barOpen` 지도에 캔버스별로, 대화 높이는 `peeks`에 에이전트별로 남겨서 전체 화면에 다녀와도 그대로예요). 전체 화면 전환은 Workspace가 넘긴 `onFull`(`setTabLayout(..., "full")`)이에요. `Panel position="bottom-center"`에 `AgentBar`와 버튼(`BarButton({ path, open })`: 닫혀 있으면 `.bar-pill` 알약, 열려 있으면 `.bar-button` 둥근 로고. 마우스를 올린 동안만 `LogoMotion`이 움직이고 끝나면 다시 그려서 로고 모양으로 멈춰요)이 있고, 접힌 에이전트 블록 클릭(`onNodeClick`, 끌기 뒤에는 오지 않아요)도 같은 상태를 바꿔요. 입력창은 채팅 화면과 같은 `Composer`이고, 에이전트가 아직 안 켜졌으면 `useAgentBoot`로 켜요. 접고 펼치는 움직임은 `useFold`(AgentNode.tsx)가 맡아요: 크기 차이의 절반만큼 위치를 옮기고, 그동안만 `.folding` 전환 클래스를 붙여요. 워커 카드는 `data.compact`와 `CARD_COMPACT`(WorktreeCard.tsx)를 써요. 접힌 블록 크기는 `COMPACT_SIZE`이고 `normalize`가 불러올 때 그 크기로 맞춰요.

- 워커 카드 확인 줄: `cardItem(selectAttention(s), path)`(attention.ts) → `AttentionRow size="compact"`(nodes/Attention.tsx)를 `.wt-card-attn`에 그려요. `QuickPrompt`는 `hidden`으로 남겨 둬요. `.wt-card-prompt`와 `.wt-card-attn`은 둘 다 `height: 48px`라 카드 높이가 바뀌지 않아요. [변경 보기]는 팝오버와 같은 `MergeDiff`(비교 창 포털)예요.
- 지도 Lead 카드의 점: `WorkerDots({ paths: wt.workers })`(status.tsx). 스토어 선택자가 `[상태, 이름]` 목록을 JSON 문자열로 돌려줘서, 다른 에이전트의 상태가 바뀌어도 점이 같으면 다시 그리지 않아요. 상태는 `glyphState` + `waitsAt`(글리프와 같은 판정).
- 카드 머리 28: `.node.wt-card > header, .node.struct-card > header`에 `min-height: var(--h-head)`, 위아래 안쪽 0(태그가 줄바꿈되는 접힌 워커 카드는 위 4 아래 8).

## 제약과 알려진 문제

- 워커 카드 확인 줄은 한 건만 보여요. 같은 워커에 승인이 여러 건이면 하나씩 답해야 다음 것이 보여요(전부는 확인할 일 팝오버에서 봐요).

- 예전에 레이아웃 토글로 저장된 `agentLayout`은 그대로 남아요. 설정 → 일반 → "열 때 화면 — 에이전트"에서 다시 고를 수 있어요.
- 화면에서 확인하지 않았어요.
